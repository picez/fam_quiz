# Quiz

Платформа живих вікторин: ведучий створює вікторину й запускає гру, гравці
приєднуються з телефонів за кодом або QR.

Специфікація: `docs/superpowers/specs/2026-10-12-quiz-live-core-design.md`.
Плани реалізації: `docs/superpowers/plans/`.

## Пакети

- `packages/shared`: схеми вікторини, відповідей, зрізів стану й подій сокета.
- `packages/engine`: чиста логіка гри без мережі й бази: перевірка відповідей,
  бали, рейтинг, етапи гри, зрізи стану для сцени, гравця й ведучого.
- `apps/server`: Fastify + Socket.IO. Кімнати живуть у пам'яті; сервер володіє
  таймером і розсилає кожній ролі її зріз стану.
- `apps/web`: клієнт на React + Vite: вхід гравця, сцена, пульт ведучого, редактор, історія.

## Команди

Потрібні Node.js 22.9+ і pnpm.

    pnpm install
    pnpm test                          # модульні тести всіх пакетів (на слабкій машині: pnpm test --maxWorkers=2)
    pnpm test --project web            # лише один пакет: shared, engine, server або web
    pnpm typecheck                     # перевірка типів
    pnpm --filter @quiz/server dev     # сервер на http://localhost:3000

## Як зіграти локально

Потрібен Docker (для бази даних).

    cp .env.example .env      # і впишіть власний BETTER_AUTH_SECRET
    pnpm install
    pnpm db:up                # PostgreSQL у Docker на порту 5433
    pnpm build
    pnpm start

Відкрийте http://localhost:3000 на комп'ютері, натисніть «Я ведучий»,
зареєструйтесь і додайте приклад вікторини або створіть власну в редакторі.
Кнопка «Грати» відкриває пульт; «Відкрити сцену» на пульті показує екран для
телевізора. Гравці з телефонів у тій самій мережі Wi-Fi заходять на адресу
комп'ютера (наприклад, http://192.168.0.10:3000) і вводять код гри або
сканують QR-код зі сцени, якщо сцену відкрито за цією ж адресою.

Під час розробки `pnpm dev` запускає сервер і клієнт із гарячим оновленням
на http://localhost:5173. Тести (`pnpm test`) бази в Docker не потребують.

## Раунди й правила раунду

Вікторина складається з одного або кількох раундів (до 10). У редакторі кнопка
«+ Раунд» додає раунд, а «Налаштування раунду» відкривають назву, бали за швидкість,
перемішування варіантів і правила підрахунку: штраф (мінус ціна запитання за хибну
відповідь), кнопку «частково» з часткою балів, бонус за серію правильних відповідей
підряд і множник ×1/×2/×3. Правила діють лише в межах свого раунду; за типових значень
раунд грається, як звичайна вікторина. Вікторина з кількома раундами проходить етапи
«заставка раунду, запитання, підсумки раунду»; ведучий може завершити раунд
достроково кнопкою «Завершити раунд» (в останньому раунді вона називається
«Завершити гру»), а історія групує запитання за раундами. Рахунок може бути від'ємним.

## Зображення до запитань

У редакторі до запитання можна додати зображення: JPEG, PNG або WebP. Фото до 20 МБ браузер сам
зменшує до 1600 px (аватар до 512 px) і стискає у WebP перед завантаженням; сервер приймає файли до 2 МБ.
Локально файли лежать у теці `apps/server/uploads` (змінюється через `UPLOAD_DIR`).
Якщо задано чотири змінні `R2_*` (див. `.env.example`), зображення зберігаються
в Cloudflare R2; це потрібно там, де диск сервера не зберігається між запусками.

## Вхід через Google

Вмикається, коли задано `GOOGLE_CLIENT_ID` і `GOOGLE_CLIENT_SECRET`; без них на
сторінці входу є лише email і пароль.

1. Google Cloud Console → APIs & Services → Credentials → Create credentials →
   OAuth client ID → Web application.
2. В Authorized redirect URIs впишіть `<адреса застосунку>/api/auth/callback/google`,
   наприклад `http://localhost:3000/api/auth/callback/google`.
3. Скопіюйте Client ID і Client secret у `.env` і перезапустіть сервер.

Google не приймає адреси на кшталт `http://192.168.0.10:3000`, тому локально вхід
через Google працює лише за `http://localhost:3000`.

## Розгортання на Render

У репозиторії є `render.yaml`: вебсервіс на Node.js і база PostgreSQL.

1. Render Dashboard → New → Blueprint → виберіть цей репозиторій → Apply.
2. Жодних значень вводити не треба: секрет сесій Render згенерує сам, базу під'єднає сам.
   Необов'язкові змінні (Google, R2, власний домен) додаються пізніше у вкладці Environment.
3. Після першого розгортання застосунок відкривається за адресою сервісу
   (`https://<назва>.onrender.com`). Наступні розгортання відбуваються після push у `main`.

Що варто знати:

- `render.yaml` вибирає найменші платні тарифи: сервіс `starter` і базу `basic-256mb`
  з диском 1 ГБ (разом близько $13 на місяць). Безкоштовний сервіс засинає після простою,
  а безкоштовну базу Render видаляє приблизно через місяць разом з усіма даними.
- `TRUST_PROXY=1` означає один проксі перед сервісом. Якщо після розгортання обмеження
  частоти спрацьовує для всіх відвідувачів разом, збільште число на одиницю.
- Диск сервісу не зберігається між розгортаннями, тож для зображень задайте `R2_*`.
- Кімнати живуть у пам'яті одного процесу: нове розгортання перериває ігри, що тривають
  (вони потрапляють в історію як перервані). Сервіс має працювати в одному екземплярі.
- Для власного домену задайте `BETTER_AUTH_URL` і додайте його адресу повернення в Google.

## Тести

    pnpm test          # модульні й інтеграційні, без Docker
    pnpm e2e           # збирає клієнт і проходить гру в Chrome від реєстрації до подіуму

`pnpm test` бере кореневий `vitest.config.ts`: чотири проєкти (shared, engine, server, web), кожен шукає `*.test.ts(x)` лише у своїй `src/` (сервер — ще в `scripts/`), тож тест кладіть поруч із кодом. Робочі дерева `.claude/worktrees`, `.superpowers`, `dist` і e2e не збираються.

Наскрізні тести — `apps/server/e2e/*.e2e.ts`, по файлу на тему (у назві — частини й тема). Спільне — `helpers/setup.ts` (сервер, база, браузер, `useE2eServer()`, `flags`) і `helpers/common.ts` (помічники для кількох файлів). Кожен файл починається з `useE2eServer();` і запускається сам, файли йдуть по одному (`fileParallelism: false`):

    pnpm build
    npx vitest run --config apps/server/e2e/vitest.config.ts part25-

На слабкій машині повний прогін — `pnpm build`, потім файли по одному на передньому плані (кожен до 10 хв; великі — половинами через `-t`). Нова частина — новий файл `partNN-<тема>.e2e.ts` або дописати в тематичний; помічник для кількох файлів — у `helpers/common.ts` з `export`; очікувані помилки консолі — `flags.restarting = true` тощо. `E2E_SHOTS=1` (знімки в `apps/server/e2e/artifacts/shots/`) і `E2E_CHANNEL` працюють як раніше.

## HTTP API

- `GET /api/games/by-code/:code` перевіряє код гри.
- `POST /api/games/by-code/:code/join` з `{ "nickname": "…" }` впускає гравця
  й повертає його `token`.

Сокет підключається з `auth: { code, role, token }`, де `role` дорівнює
`host`, `stage` або `player`.

Акаунти, вікторини й ігри (потрібна сесія, крім реєстрації та входу):

- `POST /api/auth/sign-up/email`, `POST /api/auth/sign-in/email`,
  `POST /api/auth/sign-out`, `GET /api/me`, `GET /api/auth-providers`.
- `GET|POST /api/quizzes`, `GET|PUT|DELETE /api/quizzes/:id`.
- `POST /api/uploads` (тіло запиту є файлом зображення) повертає `{ "url": "/uploads/…" }`.
- `POST /api/games` з `{ "quizId": "…" }` створює гру зі збереженої вікторини
  й повертає `code`, `hostToken`, `stageToken`.
- `GET /api/games/by-code/:code/host-access` повертає ведучому токени його гри.
- `GET /api/games` і `GET /api/games/:id`: історія ігор ведучого.
- `GET /api/me/history`: ігри, у яких гравець брав участь, увійшовши в акаунт.
- `PUT /api/me/easy` з `{ "on": true }` зберігає «Легкий режим» (31) у профілі; `GET /api/me` повертає `easyMode`.
- Групи (12k; лише учасникам, чужий отримує `404 group_not_found`): `GET|POST /api/groups`,
  `GET|PUT|DELETE /api/groups/:id`, `POST /api/groups/:id/code` (нове посилання), `POST /api/groups/:id/owner`,
  `DELETE /api/groups/:id/members/:userId`, `POST /api/groups/:id/leave`, `POST /api/groups/:id/invites`,
  `DELETE /api/groups/:id/invites/:userId`, `GET|POST /api/groups/:id/items`, `PUT|DELETE /api/groups/:id/items/:itemId`,
  `POST /api/groups/:id/uses` (12l: «використано у «…»» — лише свої вікторини й видимі записи);
  вступ за посиланням — `GET|POST /api/groups/join/:code`; запрошення до мене — `GET /api/me/group-invites`,
  `POST /api/me/group-invites/:id/accept`, `DELETE /api/me/group-invites/:id`.
