# 74. Зручний редактор вікторини — дизайн

Дата: 2026-11-23. Запит власника: «зробити зручнішим вікно розробки вікторини, зараз дуже багато всього і всюду, треба згрупувати, пододавати гарних комбобоксів, розробити максимально зручно. Також при створенні певних типів питань зробити поля обов'язковими до заповнення, або хоча б нагадування». Власник вибрав варіант А: вкладки + групи.

## Навіщо

Зараз редактор (`apps/web/src/editor/QuizEditor.tsx`) — одна довга сторінка: назва, п'ять розгорток загальних налаштувань (правила, команди, бафи, запасні, дуелі), смуга раундів із п'ятьма кнопками, «Налаштування раунду», список запитань, стіна з ~27 кнопок-типів і всі поля запитання підряд. Помилки видно лише після «Зберегти» — списком у нижній панелі. Автор, який пише запитання, весь час гортає повз те, що йому зараз не потрібне, і не бачить, що забув заповнити, доки не натисне «Зберегти».

Успіх: автор пише запитання за запитанням, не гортаючи загальні налаштування; тип вибирає зі списку з пошуком; одразу бачить, які поля обов'язкові й що в якому запитанні не так.

## Цілі

1. **Дві вкладки** під назвою вікторини: «Загальне» і «Раунди й запитання».
2. **Згруповані поля запитання** у картки з заголовками.
3. **Комбобокси** (випадні списки з пошуком і групами) замість стін кнопок: тип запитання, вибір раунду.
4. **Обов'язкові поля й нагадування** просто під час редагування, а не лише при збереженні.

## Не цілі

- Не міняємо схему даних, сервер і `GAME_STATE_VERSION`. Жодних міграцій.
- Не переробляємо внутрішні редактори окремих типів (BoardEditor, CrosswordEditor, WallEditor тощо) — вони лише переїжджають у нову картку «Відповіді». Дрібні правки в них допустимі лише для позначок обов'язковості.
- Не міняємо правила валідації `problemsOf` / `problemKey` — лише показуємо їх раніше й ближче до поля.

## Анти-цілі (провал, навіть якщо «працює»)

- Більше кліків на звичний шлях «тип → текст → відповіді → наступне запитання», ніж зараз.
- Червоні рамки на щойно створеному порожньому запитанні (помилки до того, як автор щось торкнувся).
- Збережена вікторина, яку раніше можна було зберегти, тепер не зберігається через «нагадування».
- Щось із наявних налаштувань стало недоступним або загубилося.

## Підходи (розглянуті)

- **А. Вкладки + групи + комбобокси (вибрано власником).** Загальне окремо від роботи над запитаннями; найменша переробка, яка прибирає хаос.
- Б. Покроковий майстер (Загальне → Раунди → Запитання → Перевірка). Новачку просто, але правити готову вікторину повільно — відкинуто.
- В. Три колонки на ПК (дерево / редактор / панель перевірки). Найзручніше на ПК, але найбільша переробка — відкинуто; ідею живої панелі перевірки взято у вигляді лічильника «⚠ N» (нижче).

## Дизайн

### 1. Шапка й вкладки

```
Нова вікторина                                   Довідка ведучого ↗
Назва вікторини * [ Відео 36                              ]
[ Загальне ⚠1 ] [ Раунди й запитання ⚠3 ]                ⚠ 4 зауваження ▾
```

- Назва вікторини лишається над вкладками (видно завжди), позначена `*`.
- Вкладки — `role="tablist"`, стан у URL-параметрі `?tab=general|rounds` (як інші екрани з вкладками); за замовчуванням «Раунди й запитання» для наявної вікторини і для нової.
- На вкладці — значок із кількістю **помилок** (не м'яких нагадувань) на ній.
- Праворуч кнопка «⚠ N зауважень»: відкриває панель зі списком усіх помилок і нагадувань; клік по рядку перемикає вкладку, раунд і запитання (чи клітинку дошки) і прокручує до поля. Без проблем кнопка показує «✓ Усе заповнено» (неклікабельна або прихована — рішення будівельника).
- Нижня закріплена панель «Скасувати / Зберегти» лишається. Список помилок у ній замінюється однорядковим «Не збережено: N помилок — показати» (відкриває ту саму панель).

### 2. Вкладка «Загальне»

Ті самі налаштування, що зараз, але як картки з заголовками у два стовпці на широкому екрані (один — на телефоні):

- **Про вікторину:** опис.
- **Як грати:** рейтинг (select), новачки, сімейна гра, штраф за вихід — з наявними підказками й HelpButton.
- **Командна гра**, **Бафи й дебафи**, **Запасні запитання**, **Дуелі** — окремі картки; великі (бафи, запасні, дуелі) лишаються згортаними, з коротким підсумком у заголовку картки («Дуелі: 3 категорії», «Запасні: 2», «Бафи: 5 увімкнено» / «вимкнено»).
- Наявна логіка «відкрити розгортку, якщо в ній помилка» стає «перемкнути на цю вкладку й розгорнути картку».

### 3. Вкладка «Раунди й запитання»

```
Раунд [ 2 · Відео (класичний) ▾ ]  [ + Раунд ]  [ ⋯ ]      ⚙ Налаштування раунду
┌ Запитання ─────────┐ ┌─────────────────────────────────────────────┐
│ 1 Що це за відео? ⚠│ │ Тип [ 🎬 Відео ▾ ]                      ⓘ   │
│ 2 Хто співає?      │ │ ┌ Запитання * ─────────────────────────────┐│
│ + Додати  Із групи │ │ │ текст, підказка                          ││
│   З банку          │ │ └──────────────────────────────────────────┘│
└────────────────────┘ │ ┌ Медіа ▸ (картинка / відео / звук) ───────┐│
                       │ ┌ Відповіді * ──────────────────────────────┐│
                       │ ┌ Час і бали ───────────────────────────────┐│
                       │ [Дублювати] [Вище] [Нижче] [Видалити]        │
                       └─────────────────────────────────────────────┘
```

- **Вибір раунду** — комбобокс: «номер · назва (тип раунду)», з ⚠ біля раунду з помилками. Поруч «+ Раунд» і меню «⋯» з діями: Перейменувати, Вище, Нижче, Видалити раунд (з наявними підтвердженнями). Нічого з наявних дій не зникає.
- **⚙ Налаштування раунду** — та сама розгортка `RoundSettings`, лише відкривається кнопкою поруч із вибором раунду; ⚠ на кнопці, якщо помилка в налаштуваннях раунду.
- **Список запитань** ліворуч — як зараз (перетягування, ціни, лайки, тип), плюс ⚠ біля запитань із помилкою (`problemKey` ≠ null) і м'який значок ⓘ біля запитань лише з нагадуваннями. Кнопки додавання («Додати запитання», «Із групи», «З банку») — як зараз.
- Раунди «Дошка», «Фінал», «Правда про гравця» показують свої наявні редактори в тій самій оболонці.

### 4. Редактор запитання — картки

Порядок і вміст карток:

1. **Тип** — комбобокс над картками (див. §5) + HelpButton.
2. **Запитання** `*` — текст запитання (крім `wordle`), поле ставок (`BetsCutField`), підказка.
3. **Медіа** — картинка, режим проявлення, відео, звук. Згорнута, коли медіа немає (у заголовку «Додати картинку, відео чи звук»); розгорнута, коли щось є (у заголовку підсумок «картинка», «відео з 0:42» тощо). Для типів, де медіа — суть (мелодія, відеокліп, пазл, відмінності, пам'ять, точка), медіа лишається там, де його зараз показує їхній редактор, а картка «Медіа» не показується.
4. **Відповіді** `*` — наявний `Body` для типу (варіанти, пари, слова, стіна тощо).
5. **Час і бали** — наявна пара полів таймера й балів (і примітки «без балів» тощо).

Видимість полів — рівно та сама, що зараз (усі умови `showTime`, `showPoints`, типи без підказки тощо переносяться без змін). Картки — це лише групування.

### 5. Комбобокс типу запитання

- Спільний компонент `ui/Combobox` (без сторонньої бібліотеки, як `NumberInput`): кнопка з поточним значенням → випадний список з полем пошуку, групами й клавіатурою (стрілки, Enter, Esc, введення літер фільтрує). ARIA-шаблон combobox + listbox. На телефоні — той самий список на всю ширину екрана знизу.
- Групи типів (лише ті типи, що дозволені в раунді — `questionTypesFor`):
  - **Вибір:** один варіант, кілька варіантів, так чи ні, порядок, пари, сортування, повзунок.
  - **Ввести відповідь:** текст, число, ланцюжок, драбина слів, слова з літер, список на час, вгадай слово.
  - **Медіа:** мелодія, відео(кліп), малюнок, точка, пазл, відмінності, пам'ять.
  - **Ігри й головоломки:** хто я?, стіна, більше чи менше, блеф, шпигун, кросворд, судоку, «думай інакше»…
  - **Опитування (без балів):** опитування, хмара, 100 до 1.
  Остаточний розподіл — за будівельником (кожен тип рівно в одній групі; тест, що всі `QUESTION_TYPES` покриті).
- Рядок списку: значок + повна назва (`type_*`) + однорядковий опис (новий ключ `typeDesc_*`, 7 мов).
- Зміна типу на запитанні, де вже є відповіді, яких новий тип не збереже, — як зараз (`changeType`); підтвердження не додаємо.

Той самий компонент використати для вибору раунду (§3). Інші наявні `<select>` (рейтинг, режими перевірки в налаштуваннях раунду) лишаються рідними select — вони короткі й зручні на телефоні.

### 6. Обов'язкові поля й нагадування

**Помилки** (блокують збереження, як зараз) — з наявних `problemKey` / `problemsOf` / `firstProblem` / `cellIssue`:

- Позначка `*` біля обов'язкових полів: назва вікторини, текст запитання, картка «Відповіді» (і обов'язкові поля всередині типів, де це очевидно: слово у wordle, правильна відповідь, варіанти).
- Для поточного запитання під заголовком картки, якої стосується проблема, — текст проблеми (той самий, що зараз у списку) і червона рамка картки. Потрібна мапа «ключ проблеми → картка» (Запитання / Медіа / Відповіді / Час і бали / Налаштування раунду); непізнаний ключ — у картку «Відповіді».
- **Коли показувати:** запитання вважається «торкнутим», коли автор змінив у ньому будь-яке поле й перейшов до іншого запитання, або після першої спроби «Зберегти». До того — лише `*` без червоного. ⚠ у списку запитань — теж лише для торкнутих (або всіх після спроби зберегти). Лічильник «⚠ N» у шапці рахує всі помилки завжди (він не кричить червоним, це просто число).
- Список у панелі «⚠ N» будується з тих самих функцій; потрібна версія `problemsOf`, що повертає разом із текстом місце (вкладка / раунд / запитання / клітинка / картка), — без зміни самих правил.

**Нагадування** (не блокують збереження; жовті/сірі, значок ⓘ):

- Таймер запитання коротший за 25 с (правило власника для якісних вікторин).
- У раунді ≥ 4 запитань «так чи ні» і всі правильні відповіді однакові.
- Вікторина без опису.
- Картинка-проявлення без картинки неможлива (вже помилка) — інших нагадувань будівельник не вигадує без погодження; перелік вище повний.

Нагадування видно у списку панелі «⚠ N» окремим розділом і як ⓘ біля запитання; при збереженні — не заважають.

### 7. Телефон і широкий екран

- Телефон (360 px): вкладки на всю ширину; список запитань схований за наявною навігацією «‹ 1/12 ☰ ›»; картки в один стовпець; комбобокс — нижній аркуш.
- Широкий екран (план 67): список ліворуч, редактор праворуч, вкладка «Загальне» у два стовпці.

### 8. Мови й тести

- Нові тексти (вкладки, назви карток, групи типів, описи типів `typeDesc_*`, «⚠ N зауважень», «Усе заповнено», нагадування) — у 7 мовах (uk у `i18n.ts`, решта в `locales/*.json`), з урахуванням `ADDED_*` у `i18n.test.ts` і `locales/checks.test.ts`.
- Юніт-тести: Combobox (клавіатура, пошук, ARIA); мапа проблем → картка; «торкнуте» запитання; групи типів покривають усі типи; нагадування.
- Наявні тести редактора (`QuizEditor*.test.tsx`, тести окремих редакторів) мають пройти — там, де вони клікають по чипах типів чи кнопках раундів, оновити на новий комбобокс.
- e2e: наявні частини, що створюють вікторини через редактор, оновити під комбобокс; нова частина 74 — скріншоти редактора 360 і 1920 px, вкладки, комбобокс типу з пошуком, ⚠ на запитанні після переходу, нагадування таймера, збереження з нагадуванням.

## Що лишається будівельнику

- Точний розподіл типів по групах і значки.
- Чи показувати «✓ Усе заповнено» чи ховати кнопку без проблем.
- Як саме виглядає нижній аркуш комбобокса на телефоні.
- Деталі мапи проблем → картка для кожного ключа.

## Уточнення після перевірки (мої рішення)

1. **Картки й комбобокс — у спільному `QuestionEditor`,** тобто всюди, де він є: основне запитання, клітинка дошки, запасні запитання, вкладені редактори. Один вигляд скрізь. Тести й e2e запасних і дошки оновлюються разом з основними.
2. **Панель «⚠ N» показує всі проблеми** з `problemsOf`, кожну з місцем. `problemsOf` перебудовується так, щоб повертати `{ text, place }`; тексти й правила не змінюються. Куди веде клік:
   - запасне запитання, дуель, команди, бафи → вкладка «Загальне», відповідна картка розгортається;
   - назва категорії дошки → раунд, категорія;
   - налаштування раунду → раунд, ⚙ розгортається;
   - назва вікторини → поле назви. Вона не рахується в жодній вкладці, бо видна над обома.

   Значок «Загальне» рахує проблеми загальних налаштувань, запасних і дуелей. Значок «Раунди й запитання» рахує решту.
3. **«Торкнуте» поза списком запитань:**
   - клітинка дошки — коли автор із неї пішов;
   - налаштування раунду, вкладка «Загальне», назва — коли поле втратило фокус після зміни.

   Після першої спроби «Зберегти» торкнуте все.
4. **Нагадування про таймер < 25 с** — лише там, де поле таймера запитання видно (`showTime`), і за власним `timeLimit` запитання. Раунди з часом на рівні раунду нагадування не отримують.
5. **Нагадування «так чи ні»:**
   - дошка рахується цілою, як `booleanCounts`;
   - запасні запитання не рахуються.
