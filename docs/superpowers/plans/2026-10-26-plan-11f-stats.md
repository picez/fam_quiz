# План 11f: Статистика — п'єдестал у профілі, бали за раундами й «+ / −» у грі

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Мета:** частина 11f специфікації `docs/superpowers/specs/2026-10-25-after-formats-design.md` (розділ 10, п. 7 побажань; рішення автора — розділ 14). Слова власника: «збирати трохи більше статистики в профіль, не лише хто переміг, а хто був другий і третій. Також показувати більше статистики під час гри, типу скільки балів в якому раунді, скільки + і скільки −».
- **Профіль** (власний і публічний, а також підсумок «Мої ігри»):
  - п'єдестал: скільки разів 1-е, 2-е і 3-є місце. Друге — лише в грі з ≥ 3 учасниками (командами), третє — з ≥ 4. Умови ті самі, що в перемоги (`isWin`): гра завершена, у гравця є бали (> 0). Спільне місце рахується за своїм номером (місця в базі вже рахуються як 1, 1, 3);
  - «у трійці» — відсоток ігор на п'єдесталі;
  - найкращий рахунок за гру;
  - середнє місце;
  - усе публічне, як ігри й перемоги;
  - рахується з наявних `PlayedGame.rank / playerCount / score`, без міграції, тож старі ігри теж рахуються;
  - у командній грі — місце команди (рядки людей уже мають копію місця й балів команди);
  - нових досягнень немає.
- **Під час гри:**
  - **розбивка балів** за раундами й за джерелами «+ / −»: відповіді (разом із серіями й бонусом за швидкість), помилки (штраф), фінал, дуелі, дебафи, коригування ведучого, бонуси раундів («Ва-банк», «Вибування», «Мільйонер»). Окремого лічильника в стані немає: розбивка рахується з записів відповідей і журналу коригувань;
  - **телефон, «Таблиця»:** колонки «Р1 Р2 … Σ» (на вузькому екрані раунди прокручуються, ім'я й Σ стоять на місці), дотик на **свій** рядок відкриває «+ / −». Чужої розбивки телефон не отримує взагалі;
  - **сцена, підсумки раунду:** біля кожного рядка «+N за раунд», під таблицею «Найкращий у раунді» й «Найбільший ривок» (хто найбільше піднявся місцями), якщо є;
  - **пульт:** згорнута панель «Бали за раундами» з колонками раундів; дотик на будь-кого відкриває його «+ / −»;
  - **історія гри (ведучий):** таблиця «учасник × раунд» з «+ / −». Для старих ігор вона береться з рядків відповідей і коригувань у базі, тож теж працює.

**Стан гри не змінюється:** `GAME_STATE_VERSION` той самий, нових ключів `GameState` немає, `restore.ts` не змінюється, міграцій бази немає. Нові лише поля зрізів (`Standing.rounds`, `PlayerView.myBreakdown`, `HostView.breakdowns`) і відповідей API (`GameStanding.rounds`, `GameStanding.breakdown`, нові поля `ProfileStats`). Пуш живих ігор не обриває.

**Рішення плану там, де специфікація мовчить (координатор може змінити):**

*Джерела (`ScoreSource`)*
- `SCORE_SOURCES = ['answers', 'final', 'duel', 'debuff', 'host', 'wipeout', 'survival', 'ladder'] as const` — це й порядок рядків розбивки.
- **Рядок відповіді** (запис запитання, спроба бліцу, штраф бліц-клітинки, мовчання у фіналі) має джерело за типом раунду (`answerSource`):
  - `final` → `'final'`;
  - `wipeout` → `'wipeout'` (банк «Ва-банк» лежить у балах запису запитання, на якому його забрали чи донесли, — `withWipeoutPoints`);
  - решта й невідомий тип (зіпсований знімок) → `'answers'`.
- **Коригування** має джерело зі свого `source` (`adjustmentSource`): `host`, `duel`, `debuff`, `survival` (бонус «Вибування»), `ladder` (виграш «Мільйонера»). `adjustmentSource` будується з `Record<AdjustmentSource, ScoreSource>`: нове джерело коригувань без запису не пройде typecheck.
- **Плюс і мінус** — за знаком кожного рядка. Тож «помилки» = мінуси джерела `'answers'`: штраф раунду за неправильну відповідь, неправильні спроби бліцу, штраф бліц-клітинки «мінус для всіх». Плюси `'answers'` — правильні й часткові відповіді з серіями, бонусом швидкості й бафом «подвійні», а також бали залу «Мільйонера».
- Рядки з 0 балів не враховуються (голоси опитувань і хмари, учасник «Мільйонера» на запитанні, невідповіді без штрафу).
- `ScorePart = { source, plus, minus }`: `plus ≥ 0` — сума додатних рядків, `minus ≤ 0` — сума від'ємних. `ScoreBreakdown = { parts, plus, minus }`: у `parts` лише джерела з ненульовим `plus` чи `minus`, у порядку `SCORE_SOURCES`; `plus + minus` — рахунок із цих рядків.

*Рядки рушія (`scoreLines`)*
- Ті самі рядки, що `recorder.ts` (`answerRows`) пише в базу, тож жива розбивка й історія збігаються:
  - запис закритого запитання (індекс `< closedCount`: на етапі `question` відкрите запитання — останнє в журналі й не рахується, як у `withTotals`) поза бліцем → один рядок `record.points`;
  - бліц → рядок на кожну спробу гравця (`attempt.points`, плюс `record.streakBonus` у правильній), і окремий рядок залишку `record.points − Σ` спроб (штраф бліц-клітинки), якщо він не 0;
  - гравці — `state.players` (у командній грі це команди; голоси людей мають 0 балів і не потрапляють);
  - коригування — у порядку `seq`, `questionIndex: null`.
- **Інваріант:** для кожного гравця Σ `points` його рядків = `player.score`. Його перевіряє задача 2 на станах усіх форматів.
- `scoreLines` кешується в `WeakMap<GameState, …>`: зріз будується для кожного телефону, а стан незмінний.

*Колонки раундів (`rounds`)*
- `roundCount(state)`: у лобі й до першого раунду (`guide`, `roundIndex < 0`) — 0; інакше `min(quiz.rounds.length, roundIndex + 1)`. Майбутніх раундів у таблиці немає.
- `rounds[i]` — сума рядків раунду `i` (`roundTotals`). Коригування належить раунду, у якому його зроблено (`ScoreAdjustment.roundIndex`): бали від ведучого на підсумках раунду 1 — у колонці «Р1».
- Колонки додаються до `Standing` полем `rounds?: number[]` (необов'язковим: `rankPlayers` і сервер його не знають, старі фікстури вебу без нього). Зрізи заповнюють його завжди:
  - `publicStandings` (сцена й телефони) і `hostView.standings` — з усіх рядків;
  - `liveTable` (аркуш «Таблиця» на телефоні) — з видимих рядків (нижче).
- **Історія:** `GameStanding.rounds` — `roundCount` гри = найбільший `roundIndex` серед зіграних запитань, рядків `answer` і коригувань + 1 (0, якщо нічого немає); однаковий для всіх рядків таблиці.

*Що ховається (анти-ціль «раніше, ніж таблиця»)*
- Телефон бачить у колонках і своїй розбивці рівно те, що бачить у рахунку таблиці. `visibleLines(lines, state, hidden)` для кожного гравця з `h = hidden(id) ≠ 0` бере його рядки поточного запитання (`questionIndex === state.questionIndex`):
  - їхня сума дорівнює `h` → усі відкидаються (`locked`, утримання спойлера, банк у відкритому вікні «Ва-банк»);
  - інакше це частково розкритий фінал (один рядок) → його бали зменшуються на `h`, рядок 0 відкидається.
- `hidden` для глядача `viewer` — `hiddenPoints(state, id) + (id === viewer ? 0 : windowCash(state, id))`, тобто ті самі функції, що вже ховають рахунок у `liveTable` і `me.score`.
- **Наслідок:** для кожного рядка аркуша Σ `rounds` = `score`, а `myBreakdown.plus + myBreakdown.minus` = `me.score`. Задача 2 перевіряє це на `locked`, у вікні «Ва-банк» і на кожному кроці розкриття фіналу.
- Сцена бачить таблицю лише на `leaderboard / round_end / finished` (`publicStandings`), де нічого не сховано. Пульт бачить усе.

*Хто що отримує*
- **Телефон:** `PlayerView.myBreakdown` — розбивка свого учасника рушія (у командній грі — своєї команди, той самий id, що `view.me.id`), з видимих рядків; `null` у лобі (і в `lobbyView`). Розбивок інших немає ні в якому полі. Колонки — у рядках `table` (лише свій рядок, коли `full === false`) і `standings`.
- **Сцена:** лише `standings[].rounds`. Жодних розбивок.
- **Пульт:** `HostView.breakdowns: Record<string, ScoreBreakdown>` — для кожного `state.players` (у командній грі — команд); `{}` у лобі. Без приховування.
- **Історія:** ведучий бачить розбивки всіх (`GameStanding.breakdown`). Гравцям окремої сторінки гри немає й ця частина її не додає.

*П'єдестал (`podiumStats`)*
- `podiumPlace(game)`: `1` — `isWin(game)`; `2` — завершена, `rank === 2`, `score > 0`, `playerCount ≥ 3`; `3` — завершена, `rank === 3`, `score > 0`, `playerCount ≥ 4`; інакше `null`.
- «Ігри з місцем» (`rated`): `status === 'finished'`, `rank !== null`, `playerCount > 1`. Гра наодинці не тягне середнє місце й відсоток угору.
- `top3` = `round(кількість podiumPlace ≠ null / rated × 100)`; `null`, якщо `rated` порожні.
- `avgPlace` = середнє `rank` серед `rated`, округлене до десятої (`Math.round(x × 10) / 10`); `null`, якщо порожні.
- `bestScore` = найбільший `score` серед завершених ігор (і наодинці теж); `null`, якщо завершених немає.
- `ProfileStats` отримує `podium: { first, second, third }`, `top3`, `bestScore`, `avgPlace`. `wins` лишається (`podium.first === wins` завжди).

*Вигляд*
- **Аркуш «Таблиця» (телефон).** `ScoreTable size="phone"` замість `Standings`: таблиця «#, Учасник, Р1…Рn, Σ» у власному горизонтальному скролері; ім'я й Σ закріплені (`position: sticky`). Лише свій рядок має кнопку-ім'я (`button.score-row-toggle`), дотик відкриває під рядком «+ / −» і **не закриває** аркуш (`stopPropagation`). Дотик будь-де ще закриває аркуш, як і раніше.
- **Розбивка (`BreakdownView`).**
  - Угорі «Плюс 1 050 · мінус 1 000» (числа без знака, щоб не плутати).
  - Далі рядки в порядку `SCORE_SOURCES`, у кожного джерела спершу плюс, потім мінус:
    - «Відповіді +1000» / «Помилки −1000»;
    - «Фінал», «Дуелі», «Дебафи», «Ведучий», «„Ва-банк“», «„Вибування“», «„Мільйонер“» з `+N` чи `−N`.
  - Порожня — «Балів ще немає.».
- **Сцена, `round_end`.** Наявний `Standings` з новим `gains`: `span.round-gain` «+300 за раунд» / «−50 за раунд» / «0 за раунд» перед `.score`. Під таблицею `RoundHighlights`:
  - «Найкращий у раунді: Віра · +300» — найбільший приріст раунду, лише якщо він > 0; за рівного — усі імена через кому в порядку таблиці;
  - «Найбільший ривок: Оля · +1 місце» — місце до раунду рахується за `score − приріст` (спільне місце за рівних балів, без часу), ривок = місце до − місце зараз; лише якщо найбільший > 0; за рівного — усі імена.

  Рахує це веб (`roundHighlights`) з `standings[].rounds`: рушій нового поля для сцени не дає. На `finished` сцена без змін (подіум).
- **Пульт.** Під панеллю гравців (і під «Гру завершено») — `details.panel.host-scores` з `summary` «Бали за раундами», з першого раунду до кінця гри. `ScoreTable size="host"` монтується **лише відкритим** (інакше імена дублюються в DOM і ламають наявні локатори e2e). Кожен рядок має кнопку-ім'я з розбивкою з `view.breakdowns`. Панелі «Підсумки раунду» й «Гру завершено» з `Standings` лишаються як є.
- **Історія.** Нова секція `section.panel.history-scores` «Бали за раундами» після «Підсумки», лише коли `rounds` не порожні. `ScoreTable size="history"`, заголовки колонок «Р1…», у `title` — назва раунду (`roundLabel`). Розбивку відкриває кожен рядок. Склад команди — під назвою, як у «Підсумках».
- **Профіль.** Під наявними п'ятьма числами — другий `dl.stats.podium-stats` з `aria-label` «П’єдестал»: «1-е місце», «2-е місце», «3-є місце», «у трійці», «найкращий рахунок», «середнє місце». `null` → «–», середнє з комою («2,2»). Той самий `PodiumStats` стоїть у підсумку «Мої ігри» (з `podiumStats(state.data)`).

*Чого не робимо*
- нових досягнень, міграцій, ключів стану;
- розбивки інших на телефоні й будь-якої розбивки на сцені;
- колонок раундів на подіумі сцени (`finished`) і в `Standings` телефона на `leaderboard / round_end / finished` (там таблиця лишається короткою; колонки — в аркуші «Таблиця»);
- сторінки гри для гравця;
- окремої колонки «інше» для дуже старих ігор, де коригувань у базі немає (там Σ колонок може не дорівнювати рахунку — так і показується);
- командного сценарію e2e (командні зрізи й профіль членів перевіряють задачі 2 і 3);
- нового демо-вмісту (тексти e2e — без тем росії й СРСР).

## Глобальні обмеження

- **Анти-ціль:** чужа розбивка не потрапляє на телефон, жодна — на сцену; бали поточного запитання не з'являються в колонках чи розбивці телефона раніше, ніж у його таблиці. Перевіряють:
  - задача 2 — зрізи: `'myBreakdown' in stageView(s)` і `'breakdowns' in stageView(s)` / `playerView(s, …)` → `false`; JSON телефона без чужих чисел; інваріант «Σ `rounds` = `score`, `plus + minus` = `me.score`» на прихованих етапах;
  - задача 8 — сокетні кадри.
- Бали, правила, `withTotals`, `recorder.ts`, схема бази не змінюються. `gameStats` і `versus.ts` не змінюються.
- Тексти інтерфейсу — лише в `apps/web/src/i18n.ts`, тексти довідки — лише в `apps/web/src/help/*.ts`.
- Сцена 1280 × 720 без прокрутки. Телефон 360–375 px і пульт 375 px без горизонтальної прокрутки сторінки (таблиця прокручується всередині своєї обгортки).
- Кожна задача з логікою починається з тесту, що падає. Перед комітом мають бути зелені `pnpm typecheck` і `pnpm vitest run --maxWorkers=2`. Якщо PGlite падає з браком пам'яті, запускати окремо:
  - `pnpm vitest run --maxWorkers=2 packages`;
  - `pnpm vitest run --maxWorkers=1 apps/server`;
  - `pnpm vitest run --maxWorkers=2 apps/web`.
- Наскрізні тести: спершу `pnpm build`, потім `E2E_SHOTS=1 npx vitest run --config apps/server/e2e/vitest.config.ts`.
  - **Повний прогін триває близько 32 хвилин, і машині може забракнути пам'яті.** Задача 8 запускає свій сценарій (`-t "part 11f"`) і 9a, а повний прогін — **один раз у фоні** наприкінці.
  - Затримка 11b в e2e увімкнена (`pacing: true`). Кнопки пульта чекають, доки стануть активними, без снів.
