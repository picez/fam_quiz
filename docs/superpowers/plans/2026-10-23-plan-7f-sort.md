# План 7f: тип запитання «Сортування»

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Мета:** новий тип запитання `'sort'` (розділ 8 специфікації).
- Автор задає 2–4 категорії, слова (кожне з однією правильною категорією), бали за слово й «підвисання» після помилки в секундах; плюс звичайний таймер.
- Гравець бачить категорії зонами по краях екрана (2 — ліворуч/праворуч, 3 — плюс угорі, 4 — плюс унизу) і картку зі словом посередині. Картку можна перетягнути/свайпнути в зону, торкнутися зони або натиснути стрілку.
- Правильно — бали за слово й наступна картка. Неправильно — картка трусить, екран підвисає з видимим відліком, слово йде в кінець черги гравця; повторна правильна спроба теж приносить бали.
- Сцена: категорії й живий прогрес «Оля 7/12» без відповідей; на розкритті — усі слова за категоріями.
- Раунди: класичний (усі разом), поле (сортує лише той, хто вибрав клітинку, решта бачить прогрес), фінал («правильно» = усе відсортовано до кінця часу), бліц (перемагає перший, хто відсортував усе, і отримує суму за всі слова). Без відео.

**Архітектура:**
- **Дані (`shared`).** Гілка `questionSchema`: `{ ...base, type: 'sort', categories: {id, text}[2..4], words: {id, text, categoryId}[4..20], lockSeconds }`. Поле `points` у сортуванні — **бали за слово**; `points × words.length ≤ LIMITS.maxPoints` (`sort_points`). Нова `questionPrice(question)`: для сортування `points × words.length`, інакше `points` — це ціна клітинки поля. `SortAnswer` (підсумок, який складає рушій) входить у `Answer`, але не в `answerSchema`. Нова подія `player:sort` (`{ wordId, categoryId }`).
- **Протокол ходу (безпека).** Категорія жодного слова не потрапляє до клієнта до розкриття. Телефон знає лише поточну картку (`{ id, text }`); кожен хід іде на сервер, рушій перевіряє, що `wordId` — саме голова черги гравця (`sort_stale`), що підвисання минуло (`sort_locked`), і сам вирішує «правильно / ні». Відповідь сервера — новий зріз: картка змінилася (правильно) або зросли `misses` і з'явився `lockedUntil` (помилка). Ack для обох — `{ ok: true }`.
- **Стан (`engine`).** `Play.sort?: Record<playerId, SortProgress>` (`queue`, `sorted`, `misses`, `lockedUntil`, `missed`); гравця тут немає, поки він не зробив жодного ходу. Новий файл `packages/engine/src/sort.ts` за зразком `chain.ts` (`sortWord`, `scoreSort`, `shiftSortLocks`, `sortOf`). Порядок слів — `state.presented` (перемішується один раз на відкритті, однаковий для всіх).
- **Бали.** Класика: `sorted × points × множник раунду` (мінус, частково й бонус за швидкість не діють; серія — лише за повне сортування, бо неповне має `accuracy < 1`). Поле: `sorted × points × множник клітинки × множник раунду`. Бліц: переможцю `words × points × множник раунду`, решті 0. Фінал: `finalPoints`/банк за `grade`.
- **Зрізи.** `PublicQuestion.sort` — лише категорії, кількість слів, бали за слово й секунди підвисання. `BaseView.sort` (`SortInfo`) — рядки прогресу без слів. `PlayerView.me.sort` (`PlayerSort`) — лише власна поточна картка й власний стан. Розкриття — наявний `reveal: Question`.
- **Веб.** Новий `apps/web/src/screens/SortView.tsx` (`SortPlay`, `SortBoard`, `SortReveal`), його використовують `PlayerScreen`, `StageScreen`, `HostScreen`; редактор — тіло `sort` у `QuestionEditor`, примус «звичайна клітинка з телефона» у `BoardEditor`.
- **База.** `answer.payload` — `jsonb` з будь-якою `Answer`: `SortAnswer` лягає туди без міграції. Рекордер і історія загальні.

**Технології:** TypeScript, zod 4, vitest, Fastify + Socket.IO, Drizzle + PostgreSQL (PGlite у тестах), React + Vite, Playwright.

**Специфікація:** `docs/superpowers/specs/2026-10-23-after-second-game-design.md`, розділ 8 (частина 7f), анти-цілі розділу 2 («правильна відповідь потрапляє на телефон чи сцену раніше розкриття», «гра застрягає», «старі вікторини перестали відкриватися», «проста класична вікторина стала складнішою», «дебаф робить відповідь неможливою», «елементи на екрані гравця стрибають»), рішення розділу 11 («сортування: множник клітинки й раунду діє, мінус не діє, серія — лише за повне сортування»; «однаковий порядок слів, правила для фіналу й бліцу, без відео»). Найближчий зразок — план `2026-10-23-plan-6j-word-chain.md` і `packages/engine/src/chain.ts`. Частини 7a–7e уже в `main`; 7g цей план не чіпає.

**Рішення плану там, де специфікація мовчить:**
- **Межі** (`LIMITS`): категорій 2–4 (`minSortCategories`, `maxSortCategories`), назва категорії 1–30 символів (`sortCategory`, коротко, бо зона на краю телефона); слів 4–20 (`minSortWords`, `maxSortWords`), слово 1–40 символів (`sortWord`); підвисання 1–10 с, типово 3 (`minLockSeconds`, `maxLockSeconds`, `defaultLockSeconds`); бали за слово типово 100 (`defaultSortPoints`); `points × words ≤ 2000`.
- **Інші перевірки схеми:** у кожній категорії хоча б одне слово (`sort_empty_category`); слова в межах запитання не повторюються без урахування регістру й пробілів по краях (`sort_duplicate_words`); `categoryId` слова — одна з категорій (`unknown_category`); id категорій і слів унікальні (`duplicate_ids`); відео заборонене (`sort_video`).
- **Ціна на полі.** Окремої ціни клітинки для сортування немає: поле показує `questionPrice` = найбільшу можливу суму (слова × бали за слово), а бали рахуються лише за відсортовані слова. Так «ціна клітинки ігнорується» без зайвого поля в редакторі.
- **Клітинка поля з сортуванням** — завжди звичайна й з телефона: `kind: 'normal'`, власний `answerMode: 'phone'` (бліц-клітинка чи усна відповідь для сортування не мають сенсу). Схема відмовляє `sort_cell`, редактор сам ставить ці значення при виборі типу й ховає перемикачі виду й способу для такої клітинки. Штраф «мінус для всіх» не застосовується, бо він лише для бліц-клітинок.
- **Порядок слів:** перемішується `rng` на відкритті (`present`), завжди — незалежно від `shuffleOptions`: авторський порядок часто згрупований за категоріями.
- **Помилка:** `misses + 1`, слово йде в кінець черги, `lockedUntil = now + lockSeconds × 1000`, `missed` = це слово. Якщо слово лишилося одне, після підвисання воно ж і повертається. Підвисання за межу таймера просто «з'їдає» решту часу.
- **Пауза** зсуває всі `lockedUntil` на тривалість паузи (`shiftSortLocks` у `resume`); на паузі хід — `paused`.
- **Хто може ходити:** на звичайній клітинці поля — лише той, хто вибрав (`not_your_turn`), в інших раундах — усі гравці. Гравець із записом (уже все відсортував або запис створено закриттям) — `already_answered`.
- **Записи:**
  - хто відсортував усе — запис одразу: `accepted: true`, `accuracy: 1`, `grade: 'correct'`, `timeMs` = від відкриття до останнього ходу (пауза не входить, бо `startedAt` зсувається);
  - на закритті (`lockNow`, `end`) `scoreSort` дає записи тим, хто зробив хоч один хід і не закінчив: класика — `accuracy = sorted / total`, `grade` `'partial'` (якщо `sorted > 0`) або `'wrong'`, `accepted: false`, бали за відсортоване; бліц — `accuracy 0`, `'wrong'`, 0 балів; фінал — `'wrong'`, `finalPoints(ставка, false)` (далі банк перераховує `withFinalPoints`); `timeMs` = межа часу;
  - на полі той, хто вибрав, отримує запис на закритті **завжди**, навіть без жодного ходу (0 балів), — інакше `unansweredIsWrong` нарахував би мінус ціни;
  - хто не торкався (класика, бліц, фінал), запису не має — як той, хто мовчав; у фіналі мовчання, як і досі, оцінює `settleFinal`.
- **Автозакриття:** класика й фінал — наявний `autoLock` (кожен підключений має запис = усі закінчили); поле — останнє слово відсортовано → `revealNow` (як «Прийняти»); бліц — перший, хто закінчив, → `lockNow`. Інакше — таймер або «Закрити запитання» ведучого (вихід є завжди: таймер у сортування є завжди).
- **Бліц:** правила `check`, `answerWindow`, `attempts` і мінус раунду для сортування не діють; черги `play.blitz` немає. Серія: у бліц-раунді гравець без запису на сортуванні серію не обриває й не продовжує (як «не натискав»), невдалий учасник (запис з 0) — обриває. Переможця видно всім одразу після закриття (як у миттєвому бліці: ім'я не розкриває відповідей).
- **Фінал:** `check: 'manual'` для сортування не діє; ручної оцінки немає. Сцена й телефони під час фінального сортування не бачать прогресу інших (`sort: null`), а `answeredCount` рахує тих, хто зробив хоч один хід, а не тих, хто закінчив, — інакше лічильник видав би, скільки відповіли правильно.
- **Ручна оцінка** (`override`) для сортування — `wrong_phase` у всіх раундах, як для ланцюжка: перевірка однозначна, хід за ходом.
- **Spotlight** («Мільйонер») для сортування не будується: прогрес видно в `SortInfo`.
- **Дебафи:** `answerersOf` уже дає потрібне (усі або той, хто вибрав). «Заморозка» вимикає зони через наявний `fieldset disabled`, а `SortPlay` перевіряє його і для перетягування та стрілок. «Дзеркало» зсуває зони по колу кожні `MIRROR_SWAP_MS` (`rotateChoices` для `sort` обертає `question.sort.categories`); хід, як і там, зараховується за `categoryId`. Туман, бруд, гості й тремтіння працюють поверх картки без змін.
- **Жести:** pointer events (дотик і миша однаково), `touch-action: none` на картці. Відпустили над зоною — хід у цю категорію; інакше, якщо зсув ≥ 60 px, — свайп у бік домінуючої осі, якщо там є зона; інакше картка повертається на місце. Стрілки: ← категорія в лівій позиції, → у правій, ↑ у верхній, ↓ у нижній. Зони — кнопки (Tab + Enter працюють самі).
- **Поки хід летить** на сервер, картка не приймає нового ходу (без подвійних надсилань). Трусіння запускає зростання `me.sort.misses`.
- **Без стрибків:** зони й картка мають фіксовані розміри; шар підвисання — поверх області картки; рядок «7 з 12» фіксованої висоти. За `prefers-reduced-motion: reduce` — без трусіння й польоту картки, відлік лише змінює текст.
- **Поле, глядачі:** телефони інших бачать категорії й рядок прогресу того, хто сортує («Оля сортує слова · 5 з 12»), але не картку.
- **Історія:** відповідь словами «Відсортовано 12 з 12 за 41,2 с, помилок: 2» або «Відсортовано 8 з 12, помилок: 3»; під запитанням сортування — правильний розклад «Овочі: морква, буряк; Фрукти: …». Міграції немає.
- **Демо:** у «Великий ерудит» — сортування «Ссавці / Птахи / Риби» в розминці й клітинка ×2 «Дерево чи кущ?» у полі «Сад і город».

## Глобальні обмеження

- Старі вікторини, чернетки, знімки ігор, історія й профіль поводяться як зараз; новий тип з'являється лише як додаткова гілка схеми. Міграцій немає.
- Проста вікторина створюється так само: сортування — лише ще одна кнопка типу; усі його поля мають типові значення (2 категорії, 4 слова, 100 за слово, підвисання 3 с, 60 с).
- Рушій чистий: `now` і `rng` — аргументи. Бали лише цілі.
- Анти-ціль «спойлер»: до `reveal` жоден зріз сцени чи гравця не містить `categoryId` слова й жодного слова, крім власної поточної картки гравця; сцена не містить жодного слова.
- Тексти інтерфейсу українською, лише через `apps/web/src/i18n.ts`. Нові кольори — токени в `:root` у `styles.css` (`--sort-zone`, `--sort-lock`). Тема лише темна. Поля введення — у `label.field`, шрифт ≥ 16 px. Нові класи мають префікс `sort-`.
- Сенсор, миша й клавіатура. Розкладка працює на ширині 375 px (і 360 px) без горизонтальної прокрутки з 4 зонами й словом на 40 символів. Анімації — лише за `prefers-reduced-motion: no-preference`.
- Кожна задача з логікою починається з тесту, що падає. Перед комітом зелені `pnpm typecheck` і `pnpm vitest run --maxWorkers=2` (саме `--maxWorkers=2`: паралельні робітники PGlite падають на цій машині).
- Наскрізні тести: спершу `pnpm build`, потім `npx vitest run --config apps/server/e2e/vitest.config.ts`. Кадри — з `E2E_SHOTS=1` у `apps/server/e2e/artifacts/shots`.
- Після останньої задачі й фінальної рецензії гілку зливають у `main` і пушать (проєкт тестовий).

## На що дивитися рецензентові

1. **Відповіді не витікають із сокета.** До розкриття `JSON.stringify` зрізу сцени не містить жодного слова, а зріз гравця — жодного слова, крім власної поточної картки; `categoryId` немає ніде, крім `HostView.correct`. Хід лише по голові черги, тож перебрати чужі слова не можна. Тести: задача 4, `never sends a word's category or other words before the reveal`; задача 2, `only the current card can be sorted`.
2. **Підвисання — на сервері.** Хід під час підвисання відхиляється, пауза його зсуває, хибний хід повертає слово в кінець черги. Тести: задача 2, `a wrong move locks the player and sends the word to the end`, `a pause shifts the lock`.
3. **Бали за правилами раунду.** Класика: часткові бали без мінусу й без бонусу за швидкість, серія лише за повне; поле: множник клітинки, ціна ігнорується, без мінусу за мовчання; бліц: переможець отримує суму, інші 0, мовчання серію не рве; фінал: лише повне — «правильно», банк працює. Тести: задача 2 і 3, `classic points…`, `board…`, `blitz…`, `final…`.
