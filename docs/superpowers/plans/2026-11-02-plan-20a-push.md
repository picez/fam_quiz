> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Мета:** підпроєкт 4 специфікації `docs/superpowers/specs/2026-11-01-social-feed-calendar-likes-design.md`. Це Web Push для календаря 19a.
- Гравець з акаунтом вмикає сповіщення в профілі чи календарі. Підписок може бути кілька, по одній на пристрій.

## Рішення (там, де специфікація лишила місце будівникові)

- **Ключі VAPID — лише зі змінних середовища** `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`. Репозиторій публічний: у коді, тестах, `.env.example`, `render.yaml` ключів **немає**. Тести, яким потрібна пара, генерують її під час прогону (`webpush.generateVAPIDKeys()`).
  - Жодної змінної → пуші вимкнені (`null`), сервер стартує.
  - Одна чи дві з трьох, ключ не того формату (публічний — base64url 87 символів, приватний — 43) або `VAPID_SUBJECT` не `mailto:` / `https://` → `main.ts` пише причину й виходить (`process.exit(1)`), як з `GOOGLE_*` і `R2_*`.
- **Вимкнені пуші:** `GET /api/push/key` → `{ publicKey: null }`. `POST` / `DELETE /api/me/push` → 404 `push_disabled`. Тікера немає, `calendarNotify` від пушів не підключається. Веб при `publicKey: null` ховає блок «Сповіщення» повністю.
- **Тексти сповіщень формує сервіс-воркер, а не сервер.** Сервер шле структурований `PushPayload` (вид, id події, назва, час або код). `push-text.ts` складає заголовок і текст через `t()` з `i18n.ts`. Так копія лишається в `i18n.ts`, а час показується в поясі пристрою. `i18n.ts` нічого не імпортує, тож бандлиться в `sw.js` цілком.
- **Збирання сервіс-воркера:** плагін `quiz-service-worker` у `vite.config.ts` (`apply: 'build'`) у `closeBundle` викликає `build()` з Vite: `configFile: false`, `build.lib = { entry: 'src/sw.ts', formats: ['iife'], name: 'quizSw', fileName: () => 'sw.js' }`, `outDir` = той самий `dist`, `emptyOutDir: false`, `copyPublicDir: false`. Вихід — **`dist/sw.js`**, класичний скрипт без хешу (модульні сервіс-воркери в Safari ненадійні). Fastify-static віддає його з кореня, область — `/`.
  - Реєстрація: `main.tsx` → лише `import.meta.env.PROD && 'serviceWorker' in navigator` → `navigator.serviceWorker.register('/sw.js')`. У `vite dev` файла немає, тож блок «Сповіщення» там прихований (`pushSupport` бачить `!import.meta.env.PROD`).
  - Сервіс-воркер слухає лише `install` (`skipWaiting`), `activate` (`clients.claim`), `push`, `notificationclick`, `pushsubscriptionchange`. **Слухача `fetch` немає** (специфікація: не PWA-офлайн). Це перевіряє `pwa.test.ts`.
  - Типи: у веб-`tsconfig` бібліотека DOM, і `webworker` з нею конфліктує. Тож `sw.ts` описує мінімальний структурний тип `SwScope` локально й робить `self as unknown as SwScope`. Логіка — у чистих `sw-handlers.ts`, які тестуються в jsdom.
- **Хто отримує:**
  - `reminder` — ведучий + `approved`;
  - `opened` — лише `approved` (ведучий відкрив гру сам). У даних є код кімнати: його й так бачить підтверджений у стані `open`;
  - `cancelled` — `pending` + `approved` (ті, хто бачить скасовану подію). Ведучий — ні.
  - Учасник рахується лише тоді, коли ведучий досі має його в друзях (`follow(host → user)`), як у видимості 19a. Прибраний із друзів пушів не отримує.
- **Анти-спам: щонайбільше 2 нагадування на подію плюс скасування.**
  - `reminded_at` і `opened_pushed_at` ставляться атомарно (`update … where … is null returning`) **до** відправки. Повторний тік, другий процес під час розгортання чи повторне «Відкрити гру» після зниклої кімнати пушу вдруге не дають.
  - Зміна часу події `reminded_at` **не** скидає (інакше 3 пуші). Учасник бачить «Змінено» в календарі, як у 19a.
  - `cancelled` іде один раз: маршрут уже кличе `notify.cancelled` лише при `changed: true`.
- **Нагадування за годину** — `remindDue(now)`. Подія підходить, коли `cancelled_at is null`, `reminded_at is null`, `now < starts_at <= now + PUSH_REMINDER_BEFORE_MS (3_600_000)` і гра події не `finished`.
  - Подію, створену за 30 хв до початку, нагадує найближчий тік.
  - Якщо сервер лежав через усю годину до початку, після `starts_at` нагадування вже не йде.
  - Тікер `startPushReminders(service, 60_000)`: перший прогін одразу, далі щохвилини, `unref()`, зупинка в `shutdown`. Позначки в БД, тож рестарт нічого не губить і не дублює.
- **Доставка** (`deliver`): усі підписки адресатів паралельно (`Promise.allSettled`), `web-push` з `timeout: 10_000`.
  - 404 / 410 → рядок підписки видаляється;
  - інші помилки лише журналюються, підписка лишається;
  - маршрути календаря не чекають доставки: `notify` — fire-and-forget (`tell` у 19a), тож завислий push-сервіс не гальмує «Відкрити гру».
  - TTL: `reminder` 3600 с, `opened` 21600 с, `cancelled` 86400 с; `urgency: 'high'` для `reminder` і `opened`, `'normal'` для `cancelled`.
- **Підписки й приватність:**
  - лише людина з акаунтом; кожен маршрут бере `user_id` із сесії, а не з тіла;
  - `POST /api/me/push` — upsert за `endpoint`. Якщо цей `endpoint` був в іншого акаунта (пристрій перейшов до іншої людини), рядок **переходить** до поточного. Попередній власник туди більше не отримує нічого;
  - понад `PUSH_MAX_SUBSCRIPTIONS = 10` у людини — найстаріші (`created_at`) видаляються;
  - `DELETE /api/me/push { endpoint }` видаляє лише `where user_id = me and endpoint = …` і завжди відповідає 204. Чужий `endpoint` не видаляється, і відповідь не каже, чи він існує;
  - видалення акаунта → каскад FK;
  - вихід з акаунта: веб спершу `DELETE /api/me/push` поточної підписки (поки сесія жива), потім `subscription.unsubscribe()`, далі `signOut`. Збій відписки вихід не блокує.
- **Захист від SSRF:** сервер шле POST на `endpoint`, тож приймаються лише `https://` адреси відомих push-сервісів — `pushEndpointAllowed(url)`. Хост дорівнює або закінчується на `.` + один із: `fcm.googleapis.com`, `updates.push.services.mozilla.com`, `push.services.mozilla.com`, `web.push.apple.com`, `notify.windows.com`, `push.apple.com`. Інше → 400 `invalid_payload`.
- **Обмеження частоти:** `GET /api/push/key` — 60/хв на IP. `POST` / `DELETE /api/me/push` — 10/хв на людину (`perUser('push', 10)`, як у календарі).
- **Клік по сповіщенню:** `reminder` / `cancelled` → `/feed/calendar#event-<id>`, `opened` → `/play/<код>`. Якщо вікно застосунку вже відкрите, воно фокусується й переходить (`client.navigate`), інакше `clients.openWindow`. `tag: 'event-<id>'`, `renotify: true`: «гра почалась» замінює «скоро гра».
- **Зміна ключа VAPID:** підписка зі старим `applicationServerKey` мертва. Тож `PushSettings` під час відкриття порівнює ключ підписки з `publicKey` сервера. Якщо ключі різні, а дозвіл `granted`, він тихо перепідписує й зберігає нову підписку. `pushsubscriptionchange` у сервіс-воркері перепідписує тим самим ключем і шле `POST /api/me/push` (cookie сесії same-origin).
- **iOS Safari:** Web Push лише для застосунку на головному екрані (iOS 16.4+).
  - `pushSupport()` → `'supported'`, якщо є `serviceWorker`, `PushManager` і `Notification`;
  - інакше `'ios-home-screen'`, якщо це iOS (`/iPad|iPhone|iPod/` в UA або `MacIntel` з `maxTouchPoints > 1`) і застосунок **не** відкрито з головного екрана (`display-mode: standalone` / `navigator.standalone`);
  - інакше `'unsupported'`. Тоді блок прихований: старий iOS у standalone чи браузер без пушів нічого зайвого не бачать;
  - у стані `'ios-home-screen'` блок «Сповіщення» показує лише підказку `pushIosHint` без кнопки;
  - дозвіл просимо лише з дотику по кнопці: iOS інакше відмовляє.
- **Де вмикається:** розділ «Сповіщення» в `/profile` (перед кнопкою «Вийти») — повний блок. У `/feed/calendar` над списком — компактний блок, лише в станах «вимкнено» і «iOS-підказка». Увімкнене чи заборонене календар не показує, щоб не муляло. Меню не змінюється: сім пунктів.
- **Тексти** — лише українські, у `apps/web/src/i18n.ts` (один словник `uk`), тон «ти»:
  - `pushTitle: 'Сповіщення'`
  - `pushIntro: 'Нагадаємо за годину до запланованої гри і коли ведучий її відкриє.'`
  - `pushEnable: 'Увімкнути сповіщення'`
  - `pushDisable: 'Вимкнути'`
  - `pushOn: 'Сповіщення увімкнено на цьому пристрої.'`
  - `pushDenied: 'Сповіщення заборонено в налаштуваннях браузера. Дозволь їх для цього сайту, щоб отримувати нагадування.'`
  - `pushIosHint: 'На iPhone сповіщення працюють, лише коли застосунок додано на головний екран: «Поділитися» → «На початковий екран». Відкрий його звідти й увімкни сповіщення.'`
  - `pushFailed: 'Не вдалося увімкнути сповіщення. Спробуй ще раз.'`
  - `pushReminderTitle: 'Скоро гра «{title}»'`, `pushReminderBody: 'Початок о {time}. Не запізнюйся!'`
  - `pushOpenedTitle: 'Гра «{title}» почалась'`, `pushOpenedBody: 'Ведучий відкрив гру. Торкнися, щоб приєднатися.'`
  - `pushCancelledTitle: 'Гру «{title}» скасовано'`, `pushCancelledBody: 'Ведучий скасував гру {when}.'`
  - помилка `push_disabled: 'Сповіщення на сервері вимкнені.'` (через `errorText`).

## Що має зробити власник

Без цього код працює, але пуші вимкнені. Контролер проведе власника дашбордом Render крок за кроком.

1. **Згенерувати ключі один раз**, локально, у теці репозиторію після `pnpm install` (задача 2 додає `web-push`):
   ```bash
   pnpm --filter @quiz/server exec web-push generate-vapid-keys
   ```
   або без встановлення: `npx web-push generate-vapid-keys`. Команда друкує `Public Key` (87 символів) і `Private Key` (43 символи).
2. **Render → сервіс `fam-quiz` → Environment → Add Environment Variable**, три змінні:
   - `VAPID_PUBLIC_KEY` = Public Key;
   - `VAPID_PRIVATE_KEY` = Private Key;
   - `VAPID_SUBJECT` = `mailto:<пошта власника>` (адреса для зв'язку від push-сервісів; лише `mailto:` або `https://`).
3. **Save Changes** → Render перезапустить сервіс. У журналі має з'явитися `Web Push увімкнено.`
4. **Нікуди більше** ключі не класти: ні в git, ні в `.env.example`, ні в `render.yaml`, ні в пам'ять. Приватний ключ знає лише Render.
5. **Не міняти ключі без потреби.** Після заміни всі підписки мертві. Застосунок перепідпише людину, коли вона відкриє профіль чи календар, а до того пуші не прийдуть.
6. Локально (необов'язково) ті самі три рядки можна вписати в `.env`. Він не в git.

## Глобальні обмеження

- **Ключі VAPID — лише з env** (`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`). Жодного ключа в коді, тестах, фікстурах, коментарях чи документації. Тести генерують пару під час прогону.
- **Без env пуші вимкнені чисто:** сервер стартує, `GET /api/push/key` → `{ publicKey: null }`, блок «Сповіщення» прихований, усі тести зелені без ключів.
- **Приватність:** людина бачить і змінює лише власні підписки. `user_id` береться із сесії. Пуші йдуть лише учасникам, яких ведучий має в друзях. Вихід з акаунта видаляє підписку пристрою, 404 / 410 від push-сервісу видаляють її на сервері.
- **Анти-спам:** щонайбільше 2 нагадування на подію (`reminder` + `opened`) плюс `cancelled`. Позначки ставляться атомарно до відправки.
- Сервіс-воркер не має слухача `fetch` і нічого не кешує.
- `GAME_STATE_VERSION` = 22 без змін. Рушій, `GameState`, `Room`, `restore.test.ts` не змінюються.
- Меню телефона: ті самі сім пунктів, ≤ 60 px заввишки на 360 і 375 px. Восьмого пункту немає. Меню на ігрових екранах не додаємо.
- Жодного контенту про росію (правило власника). У e2e назви й вікторина — про Україну, відповіді «так»/«ні» змішані.
- Тексти інтерфейсу й сповіщень — лише в `apps/web/src/i18n.ts` через `t()` / `errorText()`, тон «ти», коротко.
- Час у сповіщенні — у поясі пристрою (`viewerZone()` з `calendar/calendar-time.ts`). Тести фіксують `Europe/Kyiv`.
- Телефон 375 px без горизонтальної прокрутки, кнопки ≥ 44 px заввишки.
- Кожна задача з логікою починається з тесту, що падає. Перед комітом мають бути зелені `pnpm typecheck` і тести:
  - `pnpm vitest run --maxWorkers=2 packages`;
  - `pnpm vitest run --maxWorkers=2 apps/server`;
  - `pnpm vitest run --maxWorkers=2 apps/web`.
- e2e: спершу `pnpm build`, потім `E2E_SHOTS=1 npx vitest run --config apps/server/e2e/vitest.config.ts -t "^part 20a"`, **лише на передньому плані**. Кадри — `apps/server/e2e/artifacts/shots/p20a-*`.
- Кожен коміт закінчується рядками:
  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_01BJmGPfDvA3k4u2NvWi6gC1
  ```
- Після останньої задачі й фінальної рецензії — злити в `main` і запушити (версія стану не змінюється). Ключі VAPID на Render ставить власник окремо (розділ «Що має зробити власник»). Пуш коду без них безпечний.
