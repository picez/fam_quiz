## Рішення

1. **Ім'я.** `QUESTION_TYPES` уже зайняте (масив у порядку редактора) — лишається як є. Таблиця зветься `QUESTION_TYPE_TRAITS`, тип запису — `QuestionTypeTraits`.
2. **Новий модуль-листок** `packages/shared/src/question-types.ts`. Він **не імпортує значень** з `./quiz` — лише `import type { RoundType, LIMITS } from './quiz'` (типи стираються, циклу під час виконання немає). Туди переїжджають `QUESTION_TYPES` і `QuestionType` (дослівно), таблиця та всі похідні списки. `quiz.ts` робить `export * from './question-types'` і імпортує потрібне для схеми — тож усі імпорти `from './quiz'`, `from './index'` і `from '@quiz/shared'` лишаються дійсними. `index.ts` не змінюється.
3. **Повнота.** `QUESTION_TYPE_TRAITS = { … } as const satisfies Record<QuestionType, QuestionTypeTraits>` — бракує ключа чи є зайвий → помилка `tsc`. Плюс тести: ключі таблиці в порядку `QUESTION_TYPES`; кожен літерал `type` з `questionSchema.options` має запис.
4. **Склад — з таблиці, порядок — `QUESTION_TYPES`.** Помічник `typesWhere(test, lead = [])` повертає типи, що пройшли `test`, у порядку `QUESTION_TYPES`; типи з `lead` (якщо пройшли) — першими, у порядку `lead`. Єдиний історичний виняток порядку — `WIPEOUT_TYPES` і `SURVIVAL_TYPES` (`numeric` перед `text`; видно в меню редактора й закріплено тестами `quiz.test.ts:1886,1919`): для них `lead = ['single', 'boolean', 'numeric']`. Решта списків уже йдуть у порядку `QUESTION_TYPES` (перевірено по кожному).
5. **Предикати лишаються через `includes`** похідного списку, а не `TRAITS[type].flag`: на вході можуть бути рядки з бази чи старого стану (`history.ts` вже стереже невідомі типи); `includes` дає `false`, а звертання до таблиці — `undefined`/виняток. Для рушія — так само (`PROGRESS_TYPES.includes(...)`).
6. **Тип похідних списків** — `readonly QuestionType[]` (не кортеж). Вузьких типів `(typeof X_TYPES)[number]` ніхто не використовує (перевірено `grep`); `tsc` підтвердить.
7. **`rounds` = меню редактора**, дослівно як зараз (з дивним, але чинним меню `truth` — раунд без власних запитань). Для `puzzles`, `wipeout`, `survival`, `quest` воно ж — білий список схеми (`*_type`), як і сьогодні (ті самі константи). Правила місця в `quizSchema` для classic/blitz/board/final/bets/auction (з нюансами клітинок поля) у 30e **не переписуються** — лише закріплюються золотим тестом.
8. **Таймер у таблиці — ключі `LIMITS`**, не числа (`time: { min: 'minJigsawTime', max: 'maxPuzzleTime' }`, тип `keyof typeof LIMITS`): число лишається в одному місці. Zod-варіанти `questionSchema` у 30e **не змінюються**; тест звіряє таблицю з `minValue`/`maxValue` їхніх `timeLimit`.
9. **Спершу піни, потім міграція.** Задачі 1–3 лише додають тести на поточний код (золота матриця вердиктів схеми, поточні списки, меню редактора, межі таймера). Міграції 5–8 не змінюють жодного з цих тестів.
10. `views.ts:994,1085,1190` (ручна оцінка у фіналі/ставках/аукціоні) — множина = L14 без wall/survey/bluff; рівносильні лише тому, що схема не пускає ці три в такі раунди. Це не «той самий список», тож у 30e не чіпаємо (див. «Далі»).
