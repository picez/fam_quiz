# План 10j: Командна гра

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Мета:** частина 10j специфікації (розділ 14, пункти 1–8). Це остання велика частина підпроєкту 10: команди зачіпають усе. Головна ідея — пункт 7: **команда — один віртуальний гравець у рушії, капітан діє від її імені**. Тоді класика, бліц, поле, фінал, «Ва-банк», «Вибування», «Мільйонер», блеф, бафи, дебафи й дуелі працюють без зміни своїх правил. Нове лише навколо них: лобі зі складом команд, хто з людей має право діяти, живі позначки, історія й профіль.
- **Увімкнення.** У налаштуваннях вікторини є перемикач «Командна гра», кількість команд (2–6) і назви. Типові назви — «Червоні», «Сині», «Зелені», «Жовті», «Фіолетові», «Помаранчеві». Ведучий може їх змінити в редакторі.
- **Склад команд.** Ведучий **вибирає спосіб у лобі для кожної гри** (рішення власника):
  - **ведучий розподіляє сам** — перетягує нікнейми між командами (або вибирає команду в списку біля нікнейма);
  - **гравці обирають самі** — кнопками команд на телефоні;
  - **випадково** — рівномірно, кнопкою «Розподілити»;
  - **кубик** — кожен кидає кубик на телефоні, результат видно на сцені. Найбільші результати йдуть у першу команду, найменші — в останню; для трьох і більше команд — смугами. Однакові результати перекидаються.

  Поки гра не почалася, ведучий може перемістити будь-кого.
- **Капітан** — перший у списку команди, ведучий може змінити. Відповідь подає капітан, решта бачить його вибір наживо, лише для перегляду. Капітан не на зв'язку — капітанство переходить до наступного учасника на зв'язку.
- **Хто діє в кожному форматі** — таблиця в розділі «Рішення». Коротко: усе робить капітан. Винятки:
  - у бліці натискає будь-хто, а відповідає той, хто натиснув;
  - у дуелі грає учасник, якого вибрав капітан;
  - голос «Запитання в залі» подають учасники інших команд;
  - опитування й «хмару слів» кожен проходить окремо.
- **Бали, таблиця, сцена.** Бали йдуть команді. Таблиця й сцена показують команди, склад видно під назвою.
- **Історія й профіль.** Історія зберігає склад команд і командні бали. Кожен учасник отримує в історії й профілі результат команди: місце, бали, перемогу. Точність і досягнення рахуються з відповідей команди. Старі записи не змінюються.
- **Довідка ведучого:** тема «Команди» (записи `team.*`, уже зарезервована в `host-help.ts`) і рядки «У командній грі…» в записах форматів, бафів, дебафів і налаштувань.
- **Демо:** нова вікторина «Командна вечірка» (`teams-quiz.ts`, `seed-demo … teams`).

**Рішення плану там, де специфікація мовчить (і рішення власника):**

*Модель*
- **Команда — гравець рушія.** У командній грі `state.players` після старту — це команди: `PlayerState` з `id` команди, `nickname` = назва, `connected` = «хоч хтось із команди на зв'язку». Увесь наявний код (бали, серії, таблиця, кола поля, ставки, драбини, привиди, дебафи, коригування) працює з командами без змін.
- Люди — **учасники** в `state.teams.members`. Кожна дія людини проходить через `actorOf`: він повертає id команди, якщо людина має право діяти за неї, інакше помилку. Виняток — голоси: «хмара», опитування й «Запитання в залі» записуються на саму людину.
- `GameState.teams?: TeamsState` — ключ є **лише в командній грі**, від лобі до кінця. Стан версій 2–9 його не має, тож ці версії лишаються читабельними (див. «Формат стану»).
  ```ts
  export interface TeamMember {
    id: string;              // id гравця кімнати (токен веде до нього)
    nickname: string;
    connected: boolean;
    /** null — ще без команди (лише в лобі). */
    teamId: string | null;
  }
  export interface TeamsState {
    form: TeamForm;                        // 'host' | 'pick' | 'random' | 'dice'
    /** Команди в порядку налаштувань; color — позиція в налаштуваннях (0…5), не змінюється після старту. */
    list: { id: string; name: string; color: number }[];
    /** Учасники в порядку приходу; порядок у команді — цей самий. */
    members: TeamMember[];
    /** Капітан, якого вибрав ведучий; немає ключа — перший за порядком. */
    captains: Record<string, string>;
    /** Кидки кубиків у лобі; null — кидків не було або їх скасовано. */
    dice: DiceState | null;
    /** Дуелянт команди в поточній дуелі; немає ключа — капітан. Очищується, коли дуелі немає. */
    duelists: Record<string, string>;
  }
  // Play:
  /** Бліц у командній грі: хто з учасників команди натиснув останнім (відповідає він); ключ — id команди. */
  buzzers?: Record<string, string>;
  ```
- **Id команд** дає сервер (`randomUUID`), бо рядок команди стає рядком `participant` (uuid). `createGame(quiz, { teamIds })`; без `teamIds` (тести рушія) — `t1…t6`.
- У лобі `state.players` у командній грі **порожній**: люди лише в `members`. `start` створює `PlayerState` для непорожніх команд.

*Налаштування*
- `settings.teams?: { count: number; names: string[] }`. Немає поля — соло (усі старі вікторини). `count` — 2…6. `names.length === count`; кожна назва — 1…20 символів після `trim`, без повторів (`normalizeText`). Інакше код вікторини `team_names`.
- **Спосіб формування — не у вікторині, а в лобі** (рішення власника: ведучий вибирає для кожної гри). Типово — `'pick'` («гравці обирають самі»): це найприродніше для телефонів, що приєднуються. Ведучий перемикає на пульті.
- Назви змінюються лише в редакторі. Кольори — за позицією в налаштуваннях (`--team-0…5`: червоний, синій, зелений, жовтий, фіолетовий, помаранчевий).

*Формування (лише лобі)*
- `pickTeam(member, team)` — лише в способі `'pick'` (інакше `team_form`). Учасник може передумати до старту.
- `assignTeam(member, team | null)` — ведучий, у будь-якому способі. Поки тур кубиків не закрито — `dice_pending`.
- `setTeamForm(form)` — склад лишається, незакритий тур кубиків скасовується (`dice: null`).
- `dealTeams(rng)` — лише `'random'`. Усіх учасників перемішує `shuffle(…, rng)` і роздає по колу, починаючи з першої команди: розміри відрізняються щонайбільше на 1. Повторний натиск перемішує заново.
- **Кубик:**
  - `startTeamDice()` — лише `'dice'`, ≥ 2 учасники (інакше `teams_few`). Тур — усі учасники на цю мить.
  - `rollTeamDie(member, rng)` — сам учасник, раз за тур (`not_your_turn`). `rollTeamRest(rng)` — ведучий кидає за решту туру.
  - Тур закривається, коли кинули всі. Нічиї перекидаються **всі**: та сама логіка, що на полі, через спільну `settleDice`.
  - Після останнього туру учасники в порядку `diceOrder` (за спаданням) розкладаються **смугами**. Розміри: `floor(n / k)`, перші `n mod k` команд отримують на одного більше. Перша смуга — перша команда. Приклад: 6, 5, (2, 3), (2, 1) при двох командах → Червоні = 6 і 5, Сині = 2·3 і 2·1.
  - Хто прийшов після старту кидків — без команди.
  - Вилучений посеред туру зникає з кидків; тур, що через це закрився, рахується (як `dropFromDice`).
- **Старт:**
  - учасники без команди розходяться в найменші команди, за рівності — у першу за порядком; роздача — в порядку приходу;
  - порожні команди відпадають;
  - лишилося < 2 команд → `teams_few`; учасників < 2 → теж `teams_few`;
  - `dice` → `null`; `players` = непорожні команди (`score 0`, `connected` = хтось із них на зв'язку).
- **Пізнього входу немає**, як і в соло-грі (`addPlayer` лише в лобі). Повернення на зв'язок — тим самим токеном.

*Капітан і хто діє*
- **Капітан:**
  - `captainOf(team)` — явний вибір ведучого (`captains[team]`, якщо учасник ще в команді) або перший за порядком приходу;
  - якщо він не на зв'язку — наступний за ним (по колу) учасник на зв'язку;
  - коли повертається — знову капітан;
  - нікого немає на зв'язку — явний чи перший (після перезапуску всі поза зв'язком).
- `setCaptain(team, member)` — ведучий, будь-коли, крім `finished`.
- `actorOf(state, memberId, act)`:

  | act | Хто | Помилка |
  |---|---|---|
  | `'captain'` | ефективний капітан своєї команди → id команди | `not_captain` |
  | `'answer'` | бліц з кнопкою — той, хто натиснув (`buzzers`); якщо його вилучено чи він не на зв'язку — капітан. Миттєвий бліц — будь-хто, поки команди немає в черзі. Опитування й «хмара» — сама людина (id людини). Решта — капітан. | `not_in_queue` / `not_captain` |
  | `'buzz'` | будь-хто з команди → id команди | — |
  | `'vote'` | сама людина (id людини); право голосу перевіряє `canVote` | — |
  | `'duel'` | дуелянт команди (`duelists[team]`, якщо він на зв'язку), інакше капітан | `not_duelist` |
  | `'self'` | сама людина (лобі: вибір команди, кубик) | — |

  - Соло-гра: `actorOf` повертає `memberId` без змін. Наявна поведінка не змінюється.
- **Що через `'captain'`:** відповідь класики, поля, фіналу, «Ва-банк», «Вибування» (і привида), «Мільйонера» (учасника й залу), ланцюжок (`guess`, `hint`), сортування, стіна, вигадка й вибір блефу, рішення «Ва-банк» і «Мільйонера», підказки драбини, випробування й двері, бафи, друга спроба, купівля дебафу, оголошення дуелі, категорія дуелі, клітинка поля, кубик поля, ставка.
- **Без подання — без відповіді.** Пункт 7 прямо замінює «найпопулярніший вибір» з пункту 3 правилом заміни капітана. Тож мовчання команди — як мовчання гравця. Рядок розділу 17 («без подання рахується вибір більшості») застарів — див. «Питання власникові».

*Формати в командах (розділ 14, пункти 4, 5, 7)*
- **Класика, «Хто я?», картинка, що проявляється, аудіо, повзунок, точка, «100 до 1», сортування, ланцюжок, стіна:** капітан; спроби й час — на команду (вони вже рахуються на гравця рушія).
- **Бліц:**
  - `actBuzz` пише `buzzers[team] = member` і викликає наявний `buzz(team)`;
  - у миттєвому бліці відповідь будь-кого стає натиском команди (`buzzers` теж);
  - спроби спільні (це спроби гравця рушія);
  - усну відповідь голови черги називає вголос той, хто натиснув; ведучий оцінює команду.
- **Поле:**
  - ходи по колу команд; клітинку вибирає й відповідає капітан;
  - на усній клітинці відповідає вголос будь-хто, ведучий позначає результат команди;
  - бліц-клітинка — як бліц;
  - кубики порядку ходів кидає капітан за команду.
- **Фінал:** одна ставка на команду з командних балів, ставить і відповідає капітан.
- **«Ва-банк», «Вибування»:**
  - команда як один гравець: рішення, випробування й двері — капітан;
  - привид-команда відповідає «для себе» через капітана.
- **«Мільйонер»:**
  - учасником стає команда; ведучий вибирає команду, «найменші бали» — команда з найменшим рахунком;
  - відповідає, бере підказки й вирішує капітан;
  - зал — **інші команди**: їхні капітани відповідають «за себе», 10 % іде команді;
  - підказка «Зал» — відповіді інших команд. *Рішення:* у драбині зал і так складається з гравців рушія, тобто команд.
- **Блеф:** одна вигадка й один вибір на команду (капітан); свою вигадку команда не вибирає.
- **Опитування й «хмара слів» — кожен окремо.**
  - Пункт 5 каже це про хмару. *Рішення:* опитування — так само, бо обидва без балів.
  - Голос записується в `play.answers` під **id людини**. `withTotals` рахує лише `state.players` (команди), тож бали не змінюються.
  - Лічильники, хмара, «100 до 1» з хмари рахують людей: популярність — частка людей, що назвали слово.
  - `autoLock` чекає присутніх людей.
- **Бафи:**
  - належать команді: бере капітан, «вже використано» — на команду;
  - текст «Підказки ведучого» бачить уся команда;
  - **«Запитання в залі»:** голосують учасники інших команд (бюлетені під id людей).
    - Класика: команда-голосувальник уже відповіла.
    - Поле: будь-яка команда, крім тієї, що вибрала клітинку.
    - `no_voters` — немає жодної такої людини на зв'язку.
- **Дебафи:**
  - купує капітан за командні бали й насилає на іншу команду; ведучий насилає на команду;
  - **ефект — лише на телефоні капітана** цільової команди (розділ 17). Решта команди бачить позначку «На капітані дебаф: …»;
  - зміниться капітан посеред запитання — ефект переходить до нового.
- **Дуелі:**
  - команда проти команди; оголошує капітан (раз за гру на команду — наявне `duelsDeclared` з id команди);
  - **дуелянта вибирає капітан на телефоні** (`pickDuelist`), поки дуель `declared` чи `category`; типово — капітан;
  - категорію вибирає капітан команди, що оголосила;
  - відповідає лише дуелянт; якщо він не на зв'язку — капітан;
  - `duelists` очищується, коли `duel` стає `null`.
- **«Як грати»:** у командній грі після сторінки «Телефон» іде сторінка `{ kind: 'teams' }`: «Ви граєте командами: відповідає капітан, решта бачить його вибір і радить уголос; у бліці відповідає той, хто натиснув; опитування й хмару кожен проходить сам».
- **Сумісність:** усі типи раундів і запитань дозволені в командній грі; редактор нічого не забороняє.

*Живі позначки (чернетка капітана)*
- Капітан шле чернетку (`player:draft`) не частіше ніж раз на 250 мс, лише поки вона змінюється. Чернетка — відповідь у формі `answerSchema`. Порожнє поле → `null`.
- Сервер тримає чернетки **в пам'яті кімнати**, а не в стані гри: `Room.drafts: Map<teamId, { questionIndex, draft }>`. Причини:
  - не тягне запис кімнати в базу й підпис запису історії на кожен дотик;
  - не потрапляє в зрізи сцени, пульта й інших команд;
  - не переживає перезапуск — це не втрата.
- Подія менеджера `{ type: 'draft', teamId }`. Сокет перезбирає зріз лише учасникам цієї команди. `manager.view` додає `team.draft` некапітанам цієї команди на етапі `question` того самого `questionIndex`.
- Чернетка є лише для полів відповіді `AnswerInput`: варіанти, кілька, так/ні, текст, число, повзунок, порядок, пари, точка, «100 до 1», «Хто я?» / картинка (текст). Також для відповіді фіналу, драбини й питання на виживання.
- Сортування, стіна й ланцюжок ідуть хід за ходом через стан. Товариші й так бачать поступ команди у своєму зрізі. Блеф, ставку й рішення некапітани бачать як «Капітан вирішує…».

*Вилучення й зв'язок*
- Ведучий вилучає **людей**: `removePlayer(memberId)`, як і раніше `host:kick`.
  - У лобі людина просто зникає (і з кидків).
  - У грі зникають її голоси (`answers` опитувань і хмари, бюлетені залу), `captains` / `duelists` / `buzzers` з нею.
  - Останній учасник команди → команда вилучається наявним шляхом `removePlayer(teamId)`: бали, коло поля, ставки, драбина, дуель — як при вилученні гравця. Команда зникає й з `teams.list`.
- `setConnected(member)`: оновлює людину; якщо змінилося «хтось із команди на зв'язку», викликає наявну гілку для команди (відлік відсутності на полі, `awaiting`, вікна «Ва-банк», голосування залу).
  - Людина повернулася — id її команди зникає з `awaiting`.
- `suspend`: усі люди поза зв'язком; `awaiting` — id команд, що були на зв'язку.
- `presentMembers(state)` — люди на зв'язку плюс усі люди команд з `awaiting`; для голосів без балів.

*Історія й профіль*
- **Рядки `participant`:**
  - **рядок команди** — `id` = id команди, `nickname` = назва, `user_id` null, `is_team` true. На ньому відповіді, штрафи й коригування, як у гравця;
  - **рядок людини** — `team_id` = id команди. `score`, `total_time_ms`, `rank` копіюються з команди; на ньому лише власні голоси опитувань і хмари (`VOTE_ATTEMPT`).
  - `team_id` посилається на рядок команди з `on delete cascade`. Вилучена команда забирає й рядки людей.
- **Усі `PlayRef`-id** (`cell.chooserId`, `wipeout.took`, `ladder.contestant`, `survival.edge` / `out`, `bluff.authors` / `picks`) — id команд, тобто рядків `participant`. Наявні функції історії працюють без змін.
- **Деталі гри ведучого:**
  - таблиця — рядки без `team_id` (соло-гравці або команди); у команди `members` — нікнейми людей;
  - відповіді на опитування й хмару — від людей;
  - `GameDetail.teams` — чи командна гра.
- **Профіль людини (пункт 8):** рядок людини дає `nickname`, `score`, `rank` (копія). Відповіді — з рядка команди (плюс власні голоси). `unplayedWipeout` / `unplayedSurvival` / `unplayedLadder` отримують id команди.
  - `playerCount` — кількість команд гри: «1 місце з 3» — місце команди. Тоді `isWin` (`rank 1`, `playerCount > 1`) — перемога команди.
  - `PlayedGame.team` — назва команди.
  - Точність — з відповідей команди (пункт 8). Пункт 6 каже «з відповідей, які подав саме він», але пункт 8 пізніший і докладніший.
- **Досягнення:**
  - `gameTables` дає гравців без `team_id`; у рядка команди — `memberUserIds`;
  - свій учасник у профілі — рядок з `userId === me` або команда з `memberUserIds.includes(me)`;
  - порівняння (бліц-раунд, фінал, камбек) — між командами;
  - `friendsPlayedWith` враховує `memberUserIds`.
- **Список ігор ведучого:** `playerCount` — люди (рядки без `is_team`).

*Формат стану*
- **`GAME_STATE_VERSION` 9 → 10**: `GameState.teams`, `Play.buzzers`. `READABLE_STATE_VERSIONS = [2, 3, 4, 5, 6, 7, 8, 9, 10]`. Стан версій 2–9 не може містити команд — живі ігри пуш не обриває.
- `SavedRoom` не змінюється: чернетки в нього не потрапляють, `playerTokens` і `playerUsers` уже ведуть до людей.

*Демо*
- Нова `apps/server/scripts/teams-quiz.ts` «Командна вечірка», `seed-demo … teams`. Налаштування: `teams: { count: 3, names: типові }`, бафи `['audience', 'double', 'retry']`, дебафи `['fog', 'shake']` з крамницею, `newcomers: true`, `leaderboard: 'each'`. Чотири раунди:
  1. класика: 3 запитання (один варіант, текст, число), опитування й хмара;
  2. бліц з кнопкою: 4 текстові запитання;
  3. поле 3 × 3 з однією усною й однією бліц-клітинкою;
  4. фінал (класичні ставки).
- Тексти не повторюють інших вікторин (`demo-quiz.test.ts`). Факти — по одному реченню в коментарі.

*Чого не робимо*
- зміни правил будь-якого формату;
- пізнього входу в команду після старту, переміщення людей між командами після старту;
- перейменування команд у лобі;
- нових досягнень;
- окремого чату команди (обговорюють уголос — пункт 7);
- відновлення чернеток після перезапуску;
- автоматичного подання чернетки, коли час сплив;
- зміни демо-вікторин, що вже є.

## Глобальні обмеження

- Рушій чистий: жодного годинника й `Math.random`; усе від `now` і `rng`.
- **Ніщо не витікає:**
  - правильна відповідь не потрапляє на телефон чи сцену раніше розкриття (наявні тести);
  - чернетка капітана — лише в зрізах некапітанів **його** команди: не на сцені, не на пульті, не в інших команд;
  - зріз іншої команди не містить відповіді команди до розкриття (як у гравців).
  
  Тести задач 4–5 — через `JSON.stringify(view)`, e2e — через кадри сокета (`socketFrames`, `framesBeforeReveal`).
- **Соло-ігри не змінюються.** Наявні тести рушія, сервера, вебу й e2e лишаються зеленими без змін (крім навмисних, див. «Порядок збирання»).
  - `actorOf` у соло-грі — тотожність;
  - зрізи соло-гри мають `teams: null`, `team: null`;
  - історія соло-гри — без `members`, `teams: false`, `team: null`.
- Тексти інтерфейсу — лише в `apps/web/src/i18n.ts`, тексти довідки — лише в `apps/web/src/help/*.ts`.
- Телефон 375 px:
  - без горизонтальної прокрутки, кнопки ≥ 44 px;
  - до шести кнопок команд — сіткою 2 × 3;
  - «Кинути кубик» — велика, по центру;
  - смуга команди — один рядок, не вища за шапку.
- Сцена 1280 × 720:
  - лобі до шести колонок команд по 8 нікнеймів без прокрутки;
  - таблиця з до шести команд і складом під назвою.
- Кожна задача з логікою починається з тесту, що падає. Перед комітом — зелені `pnpm typecheck` і `pnpm vitest run --maxWorkers=2`. Якщо PGlite падає з браком пам'яті, запускати окремо:
  - `pnpm vitest run --maxWorkers=2 packages`;
  - `pnpm vitest run --maxWorkers=1 apps/server`;
  - `pnpm vitest run --maxWorkers=2 apps/web`.
- Наскрізні тести: спершу `pnpm build`, потім `E2E_SHOTS=1 npx vitest run --config apps/server/e2e/vitest.config.ts`.
  - **Повний прогін триває близько 12 хвилин:** запускати у фоні й чекати завершення.
  - Кадри — в `apps/server/e2e/artifacts/shots`, префікс 10j — `p10j-`.
- Після останньої задачі й фінальної рецензії гілку зливають у `main` і пушать. Живі ігри пуш не обриває: `READABLE_STATE_VERSIONS` містить 9. Міграція `0012` лише додає стовпці з типовими значеннями.

## На що дивитися рецензентові

1. **Модель.** Після старту `state.players` — лише непорожні команди. Люди — у `teams.members`. Наявні формати не мають команд-специфічних гілок, крім голосів і зв'язку. Тести: задачі 2, 3.
2. **Формування.** Чотири способи:
   - `pick` — лише сам учасник;
   - ведучий переміщає будь-кого до старту;
   - `random` рівномірний;
   - кубик — нічиї перекидаються, смуги за спаданням;
   - старт роздає тих, хто без команди, у найменші й відкидає порожні; < 2 команд → `teams_few`.
   
   Тести: задача 2.
3. **Капітан.** Перший за порядком або вибраний ведучим. Не на зв'язку → наступний на зв'язку. Повернувся → знову капітан. Тести: задачі 2, 4.
4. **Хто діє.** Некапітан отримує `not_captain` на кожну дію з таблиці. Бліц: натиснув будь-хто — відповідає він. Дуель — дуелянт. Голоси «хмари», опитування й залу — від людей. Соло — без змін. Тести: задачі 3, 5.
5. **Голоси людей.** Записи під id людей не дають балів і не потрапляють у таблицю. `autoLock` чекає людей. Хмара й «100 до 1» рахують людей. Тести: задача 3.
6. **Нічого не витікає.** Чернетка — лише некапітанам своєї команди, лише на `question` поточного запитання. Сцена й інші команди її не бачать. Тести: задачі 4, 5, 12.
