## Глобальні обмеження

- Зображення лише JPEG, PNG, WebP до 2 МБ; тип перевіряється за вмістом файлу, а не за назвою.
- Адреса зображення в запитанні завжди має вигляд `/uploads/<назва>`: той самий домен, жодних чужих адрес.
- Завантажувати може лише користувач з акаунтом; частота обмежена.
- Секрети (Google, R2) лише зі змінних середовища; у репозиторії їх немає.
- Тексти інтерфейсу українською, у словнику `apps/web/src/i18n.ts`.

## На що дивитися рецензентові

1. Файл із розширенням зображення, але іншим вмістом (HTML, SVG зі скриптом): не має зберегтися й не має віддатися як сторінка.
2. Назва файлу з `..` чи `/` у `GET /uploads/:name`: не має вийти за межі сховища.
3. Зображення завелике або повільне: екран гравця не має стрибати й ховати варіанти відповіді.
4. Google не налаштовано: кнопки немає, вхід паролем працює як раніше.
5. Сховище недоступне під час гри: гра триває, замість зображення порожньо.

## Завдання

### 1. Адреса зображення в схемі (`packages/shared`)
`imageUrl` приймає `null` або рядок за шаблоном `^/uploads/[a-z0-9]{16,64}\.(jpg|png|webp)$`.
Експортується `IMAGE_LIMITS = { maxBytes: 2 * 1024 * 1024, types: ['image/jpeg','image/png','image/webp'] }`.

### 2. Сховище зображень (`apps/server/src/storage/`)
`ImageStorage { put(name, bytes, contentType): Promise<void>; get(name): Promise<{ bytes: Uint8Array; contentType: string } | null> }`.
Реалізації: `diskStorage(dir)`, `memoryStorage()` для тестів, `r2Storage({ accountId, bucket, accessKeyId, secretAccessKey, fetch? })`
через S3 API з підписом (бібліотека `aws4fetch`). `sniffImage(bytes)` повертає тип за сигнатурою або `null`.

### 3. Маршрути зображень (`apps/server/src/upload-routes.ts`)
`POST /api/uploads` (сесія, тіло є самим файлом, 20 на хвилину) → `201 { url }`;
помилки `unauthorized` 401, `bad_image` 400, `too_large` 413.
`GET /uploads/:name` віддає файл із `content-type` за сигнатурою, `x-content-type-options: nosniff`, довгим кешем; інакше 404.
`buildApp` отримує `storage`; `main.ts` вибирає R2, якщо задано `R2_*`, інакше теку `UPLOAD_DIR` (типово `apps/server/uploads`).

### 4. Зображення в клієнті (`apps/web`)
`uploadImage(file)` в `api.ts`; у редакторі над текстом запитання кнопка «Додати зображення», перегляд, «Прибрати»;
перевірка типу й розміру до надсилання; показ на пульті ведучого й в історії гри; стилі, за яких зображення не виштовхує варіанти.

### 5. Вхід через Google
Сервер: `AuthOptions.google?: { clientId, clientSecret }`, `GET /api/auth-providers` → `{ google: boolean }`.
Клієнт: кнопка «Увійти через Google» на `/login`, лише коли сервер каже, що його налаштовано.
`.env.example` і README пояснюють, де взяти ключі й яку адресу повернення вписати.

### 6. Гра лише з акаунта
`POST /api/games` приймає тільки `{ quizId }`; тимчасовий шлях із вікториною в тілі прибрано. Тести й README оновлено.

### 7. Розгортання на Render
`render.yaml` (вебсервіс Node, база, змінні), `BETTER_AUTH_URL` типово з `RENDER_EXTERNAL_URL`,
коректне завершення на `SIGTERM` (закрити сервер, базу), розділ у README.

### 8. PWA
`manifest.webmanifest`, іконки 192, 512 і maskable, `apple-touch-icon`, посилання в `index.html`.

### 9. Наскрізний сценарій
`e2e/full-game.e2e.ts`: сервер із базою в пам'яті (PGlite) і зібраним клієнтом, Chrome; ведучий реєструється,
складає вікторину з шістьма типами запитань і зображенням, двоє гравців проходять її до подіуму,
підсумок видно в історії. Команда `pnpm e2e`.

### 10. Відкладені дрібниці
Множина «бал, бали, балів» усюди; прибрати стилі `.qcard`, `.row-edit`, `.rows-edit`, `.choice-line`.

### 11. Рецензія, виправлення, злиття
Незалежний рецензент на всю гілку разом із переробкою редактора (вона рецензії ще не мала).
