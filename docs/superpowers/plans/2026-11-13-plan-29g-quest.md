> **Перед кожною задачею виконавець звіряє назви й рядки з фактичним кодом** (`git show --stat 2f288a21^1..2f288a21` — повний перелік місць, які зачепив новий тип раунду «Аукціон»; `git show --stat 1a233f48^1..1a233f48` — «Правда про гравця» з власним станом). `quest` — раунд зі **звичайними запитаннями** (як класика) і **надбудовою** поверх них: глобальне запитання, код, позиції, спроби, бонус. Там, де класика має особливу поведінку (`speedOn`, час для рівного рахунку, `UNDOABLE_ROUNDS`, `AWAY_PENALTY_ROUNDS`, `swapSpares` автопілота, прапорці `roundBrief`), `quest` поводиться **як класика**.

**Goal:** новий тип раунду `quest` («Квест із кодом»). Автор задає глобальне запитання й код (3–8 цифр чи літер, це відповідь на нього), порядок відкриття позицій коду, кількість спроб і бонус (бали або баф). Раунд — звичайні запитання (щонайменше стільки, скільки символів у коді). Кожна правильна відповідь відкриває гравцеві (команді) наступну позицію коду в заданому порядку. Код можна ввести будь-коли протягом раунду — навіть посеред запитання; неправильна спроба згоряє. Бали-бонус: `round(бонус × (1 − k / (n + 1)))`, не менше 1, де k — скільки запитань раунду вже розкрито, n — кількість запитань раунду. Баф-бонус — додаткове використання бафа всім, хто відкрив скриню (або першим N). Після запитань — ще 30 с на введення коду, потім код бачать усі.

**Architecture:**
- **Спільне (`shared/src/quest.ts`, чисте):** нормалізація коду `questKey`, частка й бонус `questShare`/`questPoints`, `QUEST_WINDOW_MS`, позиції за порядком `questSlots`. Схема раунду — у `quiz.ts`.
- **Стан (`engine/src/quest.ts`):** необов'язкові `GameState.quest?: QuestState` (лише в раунді `quest`, від `intro` до `round_end`; `enterRound` ставить і прибирає, як `ladder`) і `GameState.questBuffs?: Record<string, BuffKind[]>` (видані квестом додаткові бафи, живуть до кінця гри). **Відкриті позиції не зберігаються** — їх рахує рушій із записів відповідей розкритих запитань раунду (тож оцінка ведучого й апеляція їх оновлюють самі). Спроби, розв'язання й вікно — у `QuestState`. Бали — коригування з новим джерелом `'quest'`. `GAME_STATE_VERSION` лишається 22.
- **Етапи:** звичайний цикл класики; після розкриття останнього запитання `next` відкриває **вікно коду** на етапі `leaderboard` з годинником 30 с (як вікно «Ва-банк»); `tick` або «Далі» ведучого закриває вікно й показує код; наступне «Далі» — кінець раунду.
- **Подія:** `player:quest` `{ code }` — будь-коли в раунді (крім паузи й показаного коду); у командах — будь-хто з команди, спроби спільні.
- **Веб:** телефон — пігулка «🔐 Код» у шапці весь раунд і нижній аркуш (`QuestSheet`) з глобальним запитанням, власними позиціями й полем; на заставці раунду й у вікні — та сама панель на весь екран. Сцена — замок із позиціями (без символів), лічильники відкритих позицій, «хто відкрив скриню»; у вікні — годинник; після — код. Пульт — усе: код, чиї які позиції, усі спроби з часом, бонуси.

**Tech Stack:** TypeScript, zod 4, vitest, Fastify + Socket.IO, React 19 + Vite + Testing Library, Playwright через vitest (e2e).

**Spec:** `docs/superpowers/specs/2026-11-11-code-quest-design.md` (обов'язкова). Зразки: `docs/superpowers/plans/2026-11-10-plan-27b-auction-round.md` (новий тип раунду: усі місця), `docs/superpowers/plans/2026-10-24-plan-10g-wipeout.md` (вікно на `leaderboard`), `docs/superpowers/plans/2026-11-12-plan-29e-melody.md` (форма, захист від витоку, команди, e2e).

## Рішення плану (там, де специфікація мовчить)

- **Назва й місце.** `'quest'` стоїть у `ROUND_TYPES` у кінці (після `'ladder'`), щоб не зсувати наявні індекси. `all_rounds` зростає до 12 (`packages/shared/src/achievements.test.ts` — `all_rounds: 12`, коментар `29g: новий тип раунду`; `apps/server/src/achievements.test.ts` — перевірити).
- **Схема раунду** (`quiz.ts`):
  ```ts
  export const QUEST_TYPES = ['single', 'multi', 'boolean', 'text', 'numeric', 'order', 'match', 'slider'] as const satisfies readonly QuestionType[];
  export const QUEST_BONUS_KINDS = ['points', 'buff'] as const;
  export const questBonusSchema = z.discriminatedUnion('kind', [
    z.object({ kind: z.literal('points'), points: z.number().int().min(1).max(LIMITS.maxPoints) }),
    /** first: null — усім, хто відкрив; N — лише першим N. */
    z.object({ kind: z.literal('buff'), buff: z.enum(BUFF_KINDS), first: z.number().int().min(1).max(LIMITS.maxPlayers).nullable() }),
  ]);
  export const questRoundSchema = z.object({
    id, type: z.literal('quest'), title, description: …optional(),
    speedBonus: z.boolean(), shuffleOptions: z.boolean(), rules: roundRulesSchema,
    /** Глобальне запитання; відповідь на нього — код. */
    prompt: z.string().trim().min(1).max(LIMITS.questionText).refine(isStorable, UNSTORABLE),
    /** Код, уже нормалізований (questKey), 3…8 символів — літери чи цифри. */
    code: z.string().min(LIMITS.minQuestCode).max(LIMITS.maxQuestCode),
    /** Порядок відкриття позицій: перестановка 0…code.length − 1; типово зліва направо. */
    order: z.array(z.number().int().min(0).max(LIMITS.maxQuestCode - 1)).min(LIMITS.minQuestCode).max(LIMITS.maxQuestCode),
    tries: z.number().int().min(1).max(LIMITS.maxQuestTries),
    bonus: questBonusSchema,
    questions: z.array(questionSchema).min(LIMITS.minQuestCode).max(LIMITS.maxQuestQuestions),
  });
  ```
  `LIMITS`: `minQuestCode: 3`, `maxQuestCode: 8`, `defaultQuestTries: 3`, `maxQuestTries: 10`, `maxQuestQuestions: 20`, `defaultQuestBonus: 1000`. `rulesOf(quest)` — `round.rules` (функція вже повертає `round.rules` для всіх, кого не перелічено; оновити лише doc-коментар).
- **Перевірки `quizSchema.superRefine`** (повідомлення):
  - `quest_code` — `questKey(code) !== code` або символ поза `\p{L}\p{N}`;
  - `quest_order` — `order` не перестановка `0…code.length − 1`;
  - `quest_short` — `questions.length < code.length`;
  - `quest_type` — запитання поза `QUEST_TYPES`;
  - `quest_buff` — `bonus.kind === 'buff'` і (`buff === 'stealth'` або `buff` не в `allowedBuffs(quiz)`).
  - Наявні `*_place` і `bets_cut_place` для `quest` уже спрацьовують (`round.type !== 'classic'`); `reveal_place` теж (картинка, що проявляється, лише в класиці).
  - Раундів `quest` у вікторині може бути кілька (специфікація не обмежує).
- **Спільна логіка** (`shared/src/quest.ts`, без значень з `quiz.ts`):
  ```ts
  export const QUEST_WINDOW_MS = 30_000;
  /** NFC, верхній регістр, лише \p{L}\p{N}. */
  export function questKey(raw: string): string;
  /** Частка бонусу: 1 − k / (n + 1); k обрізається до 0…n. */
  export function questShare(after: number, count: number): number;
  /** Бали бонусу: max(1, round(bonus × questShare)). */
  export function questPoints(bonus: number, after: number, count: number): number;
  /** Символи коду для того, хто відкрив opened позицій: на позиціях order[0…opened−1] — символ, решта null; opened обрізається до довжини. */
  export function questSlots(code: string, order: readonly number[], opened: number): (string | null)[];
  /** Типовий порядок: [0, 1, …, length − 1]. */
  export function questDefaultOrder(length: number): number[];
  ```
- **Що таке k («відповідей до коду»)** — скільки запитань раунду вже **розкрито** в мить спроби: `questAfter(state)` = кількість записів `plays` цього раунду з індексом < `questionIndex` плюс поточне, якщо етап — не `question` і не `locked` (тобто `reveal`, `leaderboard`, `duel` після розкриття, `round_end`). На `intro` раунду — 0 (100 %); посеред запитання i (0-базово) — i; у вікні після запитань — n (найменша частка). Розкрито запитань менше, ніж задумано (ведучий завершив раунд) — k за фактом.
- **Відкриті позиції** — `questOpened(state, actorId)`: кількість **розкритих** запитань раунду (ті самі, що в `questAfter`), де запис учасника має `grade === 'correct'` або на це запитання є прийнята апеляція учасника з причиною `grade` (дивись `appealPassedGrade`/`Appeal.outcome` у `appeal.ts`); обрізається до `code.length`. Частково правильна — не рахується. Цифра з'являється на **розкритті** (не в мить відповіді), щоб телефон не видавав вердикт до розкриття. Оцінка ведучого (`override`) змінює запис — і позиції перераховуються самі. Запасне (`swap`) — запис учасника, рахується так само.
- **Стан** (`engine/src/game.ts`, тип — у `quest.ts`):
  ```ts
  /** Спроба коду (29g): нормалізований рядок, мить, скільки запитань раунду було розкрито (k), хто з команди ввів (лише команди), чи правильна. */
  export interface QuestTry { code: string; at: number; after: number; by?: string; right: boolean }
  /** «Квест із кодом» (29g): ключ є лише в раунді quest від intro до round_end. */
  export interface QuestState {
    /** Спроби учасника рушія (у командах — команди) у порядку введення. */
    tries: Record<string, QuestTry[]>;
    /** play — запитання раунду; window — 30 с після запитань (етап leaderboard з годинником); shown — код показано всім. */
    stage: 'play' | 'window' | 'shown';
  }
  // GameState.quest?: QuestState; GameState.questBuffs?: Record<string, BuffKind[]>
  ```
  `enterRound`: для `quest` — `quest: { tries: {}, stage: 'play' }`, для решти ключа немає (прибрати, як `ladder`). Вилучення гравця (`removePlayer` ~1245–1302) прибирає його ключ із `quest.tries` і `questBuffs`; у командах (`teams.ts`, вилучення учасника) — `by` лишається (лише для пульта).
- **Спроба** — `enterQuestCode(state, actorId, memberId, raw, now): Result`. Перевірки по черзі:
  1. раунд не `quest` або `state.quest` немає → `wrong_phase`; етап поза `intro | question | locked | reveal | leaderboard | duel` → `wrong_phase`;
  2. `state.paused` → `paused`;
  3. учасника немає → `not_found`;
  4. `stage === 'shown'` → `quest_closed`;
  5. уже є правильна спроба → `quest_solved`;
  6. неправильних спроб ≥ `round.tries` → `quest_tries`;
  7. `questKey(raw).length !== code.length` → `quest_length` (спроба **не** згоряє);
  8. такий самий рядок уже пробували → `quest_repeat` (не згоряє).
  Далі — запис `QuestTry` (`after = questAfter(state)`, `by` — лише в командах). Правильна — нагорода (нижче). Після будь-якої спроби у вікні, якщо **всі** учасники рушія (гравці чи команди) розв'язали або вичерпали спроби, вікно закривається одразу (`stage: 'shown'`, `endsAt: null`). Заставка (`notStarted`) спробі не заважає.
- **Нагорода:**
  - `points` — `addAdjustment(state, actorId, questPoints(bonus.points, after, round.questions.length), now, 'quest')`. Множник раунду не діє. Тосту «+N» немає (`lastNotice` бере лише `host`/`undo`). Скасування ведучим (12a) — як інші коригування раунду, з `UNDOABLE_ROUNDS` (+`'quest'`).
  - `buff` — якщо `first === null` або учасник серед перших `first` розв'язань раунду (за порядком `at`, за рівності — порядком у журналі): `questBuffs[actorId] = [...old, bonus.buff]`. Баф — **ще одне використання** цього бафа в грі: `buffSpent(state, actor, kind)` = `usedCount(kind) ≥ 1 + grantedCount(kind)` замінює `buffsUsed(…).includes(kind)` у `buffBlock` (~342), `takeBuff` (~373) і `playerBuffs` (`views.ts` ~3044). Слот ряду бафів отримує `left?: number` (скільки ще можна взяти), лише якщо є видані квестом. `stealth` бонусом бути не може (схема). Якщо раунд `quest` останній, баф уже ніде взяти — редактор попереджає (`questBuffLast`, не блокує).
- **Вікно після запитань.** `next` на `reveal` останнього запитання раунду `quest` (де зараз `finishRound`) → `openQuestWindow(state, now)`: `phase: 'leaderboard'`, `startedAt: now`, `endsAt: now + QUEST_WINDOW_MS`, `remainingMs: null`, `quest.stage: 'window'`; якщо всі вже розв'язали чи вичерпали спроби — одразу `stage: 'shown'`, `endsAt: null`. Помічник `questWindowOpen(state)` — як `decisionOpen` (`endsAt !== null` або пауза з `remainingMs`).
  - `tick` на `leaderboard`: вікно сплило (`now >= endsAt`) → `closeQuestWindow` (`stage: 'shown'`, `startedAt/endsAt: null`).
  - `next` на `leaderboard` раунду `quest`: вікно відкрите → `closeQuestWindow` (ведучий закриває раніше); `stage === 'shown'` → `finishRound`; інакше (таблиця між запитаннями за `leaderboard: 'each'`) — як зараз.
  - `pause`: `leaderboardClock` включає `questWindowOpen`; `resumeClock` уже продовжує `leaderboard` із `remainingMs`. `nextDeadline` (`blitz.ts`) уже віддає `endsAt` на `leaderboard`.
  - `finishRound` і `endRoundNow` (ведучий завершив раунд) ставлять `stage: 'shown'`, якщо ще ні — на `round_end` код бачать усі.
